# Поддерживаемые типы файлов редактора

Решение от 12 ноября 2026 года. Документ фиксирует реализованный набор синтаксической подсветки первого этапа и границы поддержки. Реализация и проверки отслеживаются в [задачах 9.6–9.11](openspec/changes/archive/2026-11-20-build-local-ade-mvp/tasks.md); приёмка нативной готовой поставки остаётся в этапе 13.

## Что означает поддержка

Для каждого типа из основной матрицы обязательны:

- Подсветка синтаксиса и автоматическое определение языка.
- Собственная узнаваемая иконка типа, одинаковая в дереве, файловых вкладках, результатах поиска и списках Git. Варианты одного типа используют общую иконку; различимость не зависит только от цвета.
- Подсветка обеих сторон при сравнении с диском и версиями Git вместе с обозначением различий.
- Общий набор редактора: номера строк, поиск и замена, история отмены, работа со скобками и отступами средствами выбранного режима, черновики и безопасное сохранение. Сворачивание не обещается одинаковым для всех языков.

Поддержка относится к тексту в UTF-8. Определение языка не меняет содержимое, курсор, историю отмены и черновик, не записывает файл и не запускает его содержимое. Сохранение ручных правок сохраняет LF либо CRLF и наличие BOM.

## Специальные файлы и иконки

Особое имя может задавать иконку назначения файла, сохраняя правильный режим содержимого.

| Назначение иконки | Файлы | Режим содержимого первого этапа |
| --- | --- | --- |
| Модули Go | `go.mod`, `go.sum`, `go.work`, `go.work.sum` | Обычный текст |
| Пакеты JavaScript | `package.json`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock` | JSON, YAML или обычный текст для `yarn.lock` |
| Пакеты Rust | `Cargo.toml`, `Cargo.lock` | TOML |
| Make | `Makefile`, `makefile`, `GNUmakefile`, `.mk` | Обычный текст |
| Git | `.gitignore`, `.gitattributes`, `.gitmodules`, `.gitconfig` | Обычный текст либо INI для `.gitmodules` и `.gitconfig` |
| Лицензия | `LICENSE`, `LICENSE.*`, `COPYING`, `NOTICE` | По известному расширению либо обычный текст |
| Terraform | `.tf`, `.tfvars` | Обычный текст; подсветка HCL отложена |
| Табличные данные | `.csv`, `.tsv` | Обычный текст без табличного представления |
| Текст и журналы | `.txt`, `.log` | Обычный текст с отдельными иконками текста и журнала |

Изображения, PDF, архивы, шрифты, исполняемые файлы и двоичные базы данных получают иконки своих категорий в дереве и списках Git. Иконка не означает наличие встроенного просмотра или редактирования формата. SVG открывается только как исходный XML без выполнения встроенного содержимого.

## Определение языка

Приоритет правил:

1. Специальное имя файла.
2. Наиболее точное известное расширение.
3. Известный интерпретатор в первой строке `#!`, если соответствия по имени или расширению нет.
4. Обычный текст для нераспознанного UTF-8 файла.

Для `#!` распознаются `sh`, `bash`, `zsh`, `python`, `python3` и `node` через прямой путь либо `/usr/bin/env <интерпретатор>`. Файл `.h` по умолчанию относится к C; неизвестный `.conf` открывается обычным текстом.

По уточнению от 12 ноября 2026 года переключатель языка убран из панели редактора. Язык определяется автоматически. Отсутствие подсветки не препятствует обычному редактированию, поиску, отмене, работе с черновиком и безопасному сохранению.

## Границы первого этапа

- Для Go и TypeScript/JavaScript, включая TSX/JSX, добавлены переходы по символам, поиск использований, автодополнение, подсказки типов, диагностика и переименование через готовые языковые серверы. Установка и команды описаны в [навигации по коду](docs/code-navigation.md). Остальные форматы получают синтаксическую подсветку и общие возможности редактора; отладчик и автоматическое форматирование отложены.
- Svelte, Astro, GraphQL и HCL не входят в обязательный набор подсветки; их текст в UTF-8 можно редактировать. Другие языки существующего каталога могут работать, но не считаются прошедшими приёмку.
- Файл Jupyter можно открыть как обычный текст, без выполнения ячеек.
- Встроенный просмотр Markdown, изображений и PDF, табличный редактор CSV и перекодирование отложены.
- Двоичные файлы, PDF, растровые изображения и текст в неподдерживаемой кодировке, включая UTF-16 и Windows-1251, не открываются для текстового редактирования. Показывается понятное сообщение; содержимое не заменяется, не перекодируется и не перезаписывается.

## Темы редактора

Вместе с приложением поставляются пять встроенных тем: One Dark Pro, Dracula Theme, Catppuccin Mocha, GitHub Dark Default и GitHub Light Default. Они доступны в настройках сразу после установки и работают без сети. Палитры включены в сборку интерфейса; исходные версии и лицензии указаны в [уведомлениях о темах](public/licenses/editor-themes/README.md).

В разделе «Внешний вид» можно импортировать локальный пакет тем VS Code `.vsix`. Все объявленные в пакете варианты добавляются в список «Цветовая тема редактора». Выбор применяется сразу к редактору, обеим сторонам сравнения и предпросмотру; он сохраняется для всех проектов на этом устройстве. Исходная тема Yade остаётся доступной. Повторный импорт обновляет имеющиеся варианты.

Импорт читает JSON/JSONC, внутренние включения `include` и связанные файлы TextMate `.tmTheme`, включая локализованные названия из `package.nls.json`. Файлы не извлекаются на диск, содержимое расширения не выполняется. Повреждённый пакет не заменяет уже импортированные темы. Ограничения: пакет до 64 МиБ, отдельный файл темы до 4 МиБ, до 128 вариантов в пакете и до 256 сохранённых тем. При недоступности локального хранилища показывается предупреждение.

Все 40 режимов основной матрицы и вложенные языки сохраняются. Основные цвета и общие категории правил TextMate адаптируются к тегам CodeMirror. Контекстные и языковые селекторы, а также семантические правила VS Code не воспроизводятся полностью, поэтому отдельные токены могут отличаться от оригинала. Импорт оформления не расширяет набор поддерживаемых языков.

## Основа реализации и проверка

Оставляем CodeMirror с ленивой загрузкой имеющихся режимов и ограниченный набор локальных SVG из Material Icon Theme с сохранением уведомления MIT. Сетевая загрузка иконок и расширение VS Code не требуются.

Критерии приёмки: соответствие имён и расширений всей матрице, реальные токены подсветки каждого режима, JSONC и вложенные языки, единые иконки, автоматическое определение языка без отдельного переключателя, подсветка сравнений и работа без сети. Отдельно проверяются LF, CRLF, BOM и отказ редактирования двоичных данных и неподдерживаемых кодировок. Существующие автосохранение и защита черновиков действуют для всех текстовых режимов.

Проверено 12 ноября 2026 года: [соответствия типов и локальные иконки](src/fileTypes.test.ts), [токены всей матрицы и вложенные языки](src/fileLanguages.test.ts), [автоматическое определение языка и сравнения](src/CodeEditor.test.tsx), [безопасное чтение и сохранение](src-tauri/src/editor/tests.rs). В изолированном браузере проверены дерево, вкладки, поиск и Git в текущей тёмной теме при масштабах 75%, 90%, 100%, 110%, 125% и 150%; внешние запросы запрещены, файловые команды заменены тестовыми данными. Это проверка интерфейса, а не нативного окна Tauri.

Сценарии приёмки приведены в [спецификации редактора](openspec/specs/code-editor/spec.md), технический подход — в [решении](openspec/changes/archive/2026-11-20-build-local-ade-mvp/design.md).
