# Мониторинг терминалов

При открытии мониторинга проекты упорядочиваются по последней активности. Пока панель открыта, фоновый вывод и изменения статусов не переставляют проекты; новые проекты появляются сверху. При повторном открытии порядок рассчитывается заново.

В обычных терминалах Yade Codex и Claude Code распознаются по процессам, принадлежащим PTY этого терминала. Имена алиасов и функций оболочки не используются. Поддержаны нативные исполняемые файлы и стандартные точки входа пакетов Node.js. Проверка процессов общая для терминалов и обновляется раз в 3 секунды. Запрос ограничен системными именами PTY живых терминалов Yade; запуск и завершение терминала сразу обновляют область запроса. При отсутствии таких терминалов опрос не выполняется.

На macOS список процессов, исполняемые файлы и аргументы Node.js читаются напрямую через системные интерфейсы. Они проверяются заново при каждом обновлении, включая изменение программы или аргументов внутри прежнего PID. На остальных Unix используется адресный запрос `ps` по тем же PTY.

Текущий экран восстанавливается из копии байтов PTY с учётом управляющих последовательностей и размера терминала. Результат анализа экрана кешируется; новые данные, изменение размера, смена процесса и подтверждение ввода обновляют его. Переход в состояние покоя после секундной выдержки не требует нового вывода. Снимок обзора не забирает вывод у интерфейса. Наблюдение не подменяет команды и не изменяет настройки Codex или Claude Code. Для локальной `zsh` на macOS отдельно подключается временная интеграция ввода и блоков команд; пользовательские файлы настроек загружаются обычным порядком и не редактируются.

Для Codex на переднем плане в первую очередь учитываются штатные события состояния в PTY (OSC 7501). По ним обзор сразу показывает «Работает», «Ждёт ответа», «Готов» или «Ошибка». Если событие недоступно, состояние определяется по экрану и заголовку.

- «Работает»: распознан штатный индикатор работы в заголовке либо строка прерывания текущей операции. При наличии очереди сообщений Codex поиск охватывает последние 12 непустых строк перед полем ввода.
- «Ждёт ответа»: на текущем экране есть диалог с вариантами выбора либо счётчик вопросов Codex с подсказкой `to answer`.
- «Готов»: распознано состояние покоя или пустое поле ввода без строки работы; экран не менялся минимум секунду.
- «Статус неизвестен»: убедительных признаков недостаточно, процесс приостановлен или работает в фоне, либо проверка процессов недоступна. Само отсутствие вывода не означает готовность.
- После исчезновения процесса отображается завершение работы в терминале. Код завершения вложенной команды таким способом недоступен, поэтому успешное выполнение задачи не подтверждается.

Во время подтверждения готовности сохраняется предыдущий известный статус того же процесса. При перерисовке он сохраняется до распознавания нового состояния или до 3 секунд без изменения содержимого экрана. Управляющие последовательности, которые не меняют содержимое экрана, эту выдержку не продлевают. Ожидание вывода после нажатия клавиши также сохраняет прежний статус максимум на 3 секунды. Если распознавание не восстановилось, статус становится неизвестным. Смена процесса, потеря доступа к наблюдению и приостановка сбрасывают прежний статус.

Клавиши навигации и сообщения колеса мыши не сбрасывают подтверждённый статус. Поле ввода Codex с черновиком или другой подсказкой распознаётся при наличии штатной строки подсказок ниже него.

Распознавание по экрану и заголовку зависит от видимых индикаторов. Обновления интерфейса Codex и Claude Code могут потребовать изменения правил распознавания. Проверки по номеру версии нет. Подключения через SSH, контейнеры и мультиплексоры не распознаются как локальные процессы Codex или Claude Code.

При запуске команды из оболочки учитывается вывод, полученный после отправки команды, даже если процесс обнаружен позже. Вывод и заголовок до отправки команды новому запуску не передаются.

Переключение между открытыми вкладками и обзором не останавливает наблюдение. Закрытие вкладки или отдельной панели сохраняет PTY, экран и чтение вывода до полного выхода из Yade. Вернуться к терминалу можно через обзор проектов. Действие «Завершить терминал» останавливает оболочку и её дерево процессов; `Ctrl+C` прерывает текущую команду. Когда очередь PTY заполняется, чтение приостанавливается без потери байтов. Последний подтверждённый статус сохраняется до 3 секунд, затем становится неизвестным до возобновления чтения. Для ограничения памяти модель экрана наблюдателя поддерживает до 1000 столбцов и 300 строк; больший терминал продолжает работать, но его статус неизвестен.

В локальной `zsh` поле команды закреплено внизу панели. `Enter` запускает команду, `Shift+Enter` добавляет строку; вставка текста не запускает выполнение. Подсказки используют историю `zsh`, команды, псевдонимы и пути; `Tab` подставляет выбранный вариант. Во время выполнения ввод передаётся программе через обычный терминал, включая SSH и полноэкранные программы. После завершения команда получает блок с выводом, кодом завершения и временем выполнения. Доступны копирование, сворачивание и возврат команды в поле ввода без автоматического запуска. В памяти остаются последние 100 блоков; вывод каждой команды ограничен прокруткой xterm в 2000 строк. Блоки не сохраняются между запусками приложения.

История располагается над нижним полем ввода и заполняется снизу вверх. Каталог, ветка Git и время выполнения показаны над командой; действия блока появляются при наведении или переходе к ним клавиатурой. Основное приглашение `zsh` заменяется новым полем ввода, чтобы оно не дублировалось при запуске и изменении размера. Это изменение действует только внутри запущенной оболочки; пользовательские файлы настроек остаются прежними. Панель навигации по коду скрыта на терминальной вкладке.

Терминальную вкладку можно разделять на левую и правую либо верхнюю и нижнюю панели. Каждая панель запускает независимую оболочку; для локальной `zsh` новая панель наследует текущий каталог исходной. Размер меняется разделителем, переход между панелями доступен через `Ctrl+Alt+стрелки`.

Локальные проверки используют настоящий PTY и тестовые процессы с именами Codex и Claude Code; они не подтверждают реальный подписочный запуск или совместимость всех версий.

Название терминала создаётся тем же фоновым механизмом, что и название обычного разговора: по отправленному запросу и ответу распознанного исполнителя. Запрос берётся из видимой строки ввода при нажатии Enter внутри Codex или Claude Code; после распознанного перехода от работы к готовности ожидается текст ответа. Контекст ответа начинается с его штатного маркера, до 6000 символов; команды запуска и предшествующий вывод оболочки в него не входят. Открытие исполнителя без задачи и обычная работа в оболочке не создают название. Заголовок, передаваемый терминалом, названием вкладки не становится. Название видно во вкладке и обзоре, сохраняется при повторном открытии вкладки и после завершения команды; запуск нового процесса сбрасывает его. Запрос выполняется один раз для каждого процесса, без изменения терминального ввода и истории разговоров; при ошибке остаётся исходное название. Наблюдение эвристическое: без распознанного перехода название не создаётся, а вышедший за пределы снимков текст в него не попадёт.

Для видимых панелей терминала используется WebGL-рендерер xterm. При недоступности GPU или потере контекста восстанавливается штатный рендерер без сброса буфера и PTY. Скрытые панели освобождают GPU-контекст. Новый блок вывода прокручивает историю вниз только при чтении у нижней границы; при прокрутке вверх позиция сохраняется.
