# Установка и ручное обновление macOS

## Состав поставки

`npm run desktop:build` создаёт `src-tauri/target/release/bundle/macos/Yade.app`. Внутри находятся интерфейс, ядро, Node.js **26.8.1**, `claude-bridge.ts`, `claude-settings.mjs` и зависимости SDK **0.2.141**, закреплённые в `executors/runtime/package-lock.json`. Лицензия Node.js включена в `Contents/Resources/runtime/NODE-LICENSE`. Дополнительный Claude CLI из пакета SDK не устанавливается.

Node.js для работы установленной Yade отдельно не нужен. Codex, неизменённый Claude Code и Git устанавливаются пользователем. Ограничений по номеру версии CLI нет: обнаруженная версия показывается для диагностики, ошибки входа и протокола отображаются при проверке и запуске. Версия Git определяется установленным инструментом. Штатный вход выполняется в самих CLI; Yade не переносит токены. Порядок входа и ограничения описаны в [совместимости](executor-compatibility.md).

Минимальная macOS в пакете — **13.5**, в соответствии с [требованиями Node.js](https://github.com/nodejs/node/blob/v26.8.1/BUILDING.md). Локально проверены macOS **26.3** и **Apple Silicon**. Сборочный сценарий допускает только архитектуру текущего Mac и соответствующую среду Node.js; сборка Intel на этой машине не проверялась.

## Установка

1. Скопировать целиком `Yade.app` в `/Applications` либо `~/Applications` через Finder.
2. Открыть скопированное приложение через Finder. Сервер разработки и терминал для запуска Yade не нужны.
3. Открыть «Настройки исполнителей». Если инструмент отсутствует, установить указанный CLI и полностью перезапустить Yade. Если требуется вход, выполнить указанную команду штатного входа в терминале. Ошибка подписки при ответе отображается отдельно от обнаруженного входа.
4. Добавить существующую папку проекта и открыть пространство. Для проверки Git выбрать репозиторий; для обычной папки показывается отсутствие репозитория.

При старте Yade получает `PATH` из интерактивной оболочки пользователя с ограничением проверки в пять секунд. При неудаче остаются унаследованный `PATH` и стандартные расположения: `~/.local/bin`, `~/.cargo/bin`, `~/.npm-global/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`. В готовой сборке встроенный Node.js добавляется первым; абсолютный путь найденного CLI передаётся исполнителю. Все операции Git используют общий механизм обнаружения и явный каталог репозитория. После изменения путей нужно полностью перезапустить приложение.

Сборка имеет локальную подпись ad-hoc; сертификат Developer ID и нотариальное заверение Apple не настроены. Проверка подписи: `codesign --verify --deep --strict <путь-к-Yade.app>`. Для загруженной из интернета сборки macOS может потребовать разрешить открытие в системных настройках. Это не равнозначно нотариальному заверению; подробности — в [документации Tauri](https://tauri.app/distribute/sign/macos/#ad-hoc-signing).

## Данные и обновление

Изменяемые данные находятся вне `.app`:

```text
~/Library/Application Support/dev.yade.desktop/state.sqlite3
```

Здесь хранятся проекты и ссылки на пространства, разговоры и внешние идентификаторы, сообщения, черновики файлов и сообщений, настройки и расположение представлений. Исходники и worktree хранятся отдельно от базы: новые пространства из формы создаются в `~/yade/workspaces/<имя папки репозитория>/<название пространства>`, существующие сохраняют свои пути. Резервная копия базы не включает эти папки. Штатные данные продолжения Codex и Claude остаются в их собственных хранилищах: резервная копия базы Yade их не заменяет.

Порядок ручного обновления:

1. Завершить Yade через **Cmd+Q**, подтвердить остановку активной работы и дождаться выхода. Закрытия окна недостаточно.
2. Скопировать папку `dev.yade.desktop` в отдельное безопасное расположение. Копирование выполняется при полностью остановленной Yade, включая возможные файлы SQLite `-wal` и `-shm`.
3. Заменить старую `Yade.app` новой целиком. Каталог данных и папки проектов не удалять.
4. Открыть новую версию. Проверить проекты, разговоры, настройки и оба вида черновиков. Сохранённые команды сами не запускаются; продолжение разговора требует явного действия.

Если требуется повышение версии схемы существующей базы, до миграции Yade сохраняет рядом отдельный файл:

```text
state.sqlite3.before-v<исходная-версия-схемы>-<уникальный-идентификатор>.bak
```

Копия создаётся средствами SQLite, включая сохранённые данные из WAL, и не перезаписывает предыдущие копии. При невозможности создать копию миграция не начинается. Все миграции одного открытия выполняются транзакционно. При ошибке исходная схема и данные остаются прежними; системное сообщение показывает причину и путь резервной копии. При повторном открытии уже совместимой базы новая копия автоматически не создаётся.

## Восстановление совместимой базы

Старая Yade отклоняет базу с более новой схемой. Установка старой `.app` поверх новой сама по себе не преобразует базу назад.

1. Полностью завершить Yade. Сохранить текущую папку данных отдельно, включая `-wal` и `-shm`, чтобы не потерять изменения после обновления.
2. Выбрать резервную копию, схема которой поддерживается возвращаемой версией. Копия с `before-vN` содержит схему **N**, до перехода на следующую версию.
3. Переместить текущую папку `dev.yade.desktop` в архивное расположение, создать пустую папку с тем же именем и скопировать выбранную совместимую базу в неё как `state.sqlite3`. Старые `-wal` и `-shm` в новую папку не переносить.
4. Установить соответствующую `.app` и проверить данные. Изменения, сделанные после выбранной копии, останутся только в сохранённом архиве; автоматического объединения баз нет.

Нельзя вручную уменьшать `user_version`, чтобы обойти проверку совместимости. Поддержка чтения новой схемы старым приложением и обратные миграции не заявляются.

## Повторение проверок

Для сборки нужны официальный [Node.js 26.8.1](https://nodejs.org/en/download/archive/v26.8.1), npm, Rust с Cargo и Xcode Command Line Tools. Сценарий проверяет версию и архитектуру Node.js, а также отсутствие его зависимостей от библиотек Homebrew или других внешних расположений. Зависимости среды устанавливаются через `npm ci --omit=dev --omit=optional --ignore-scripts`.

```sh
npm ci
npm run desktop:build
npm run desktop:check
npm run desktop:check-update -- <предыдущая-Yade.app> <новая-Yade.app>
cargo test --locked --manifest-path src-tauri/Cargo.toml installed_application_discovers_tools_from_a_finder_environment -- --ignored --nocapture
```

`desktop:check` копирует `.app` во временное расположение и запускает её Node.js с системным `PATH`: проверяет загрузку SDK и протокол, затем поток и настройки с подстановкой SDK. `desktop:check-update` открывает два временных настольных окна последовательно с отдельным `HOME` и системным `PATH`, проверяет миграцию и замену `.app`, затем завершает только свои процессы и удаляет временные данные. При отсутствии аргументов он проверяет повторную установку текущей сборки. Последний тест проверяет установленные CLI и Git, а также каталог моделей Claude через встроенный Node.js; сообщения не отправляются. Проверкам процессов нужен доступ к `/bin/ps` вне песочницы.

### Результаты 11 ноября 2026 года

- `.app` собрана для Apple Silicon; проверка локальной подписи проходит.
- Проверка копии `.app` без отдельного Node.js в `PATH` подтверждает встроенную среду, загрузку SDK, протокол, поток и настройки на тестовой границе. Реальный каталог моделей Claude также получен через встроенную среду.
- В окружении без путей терминала разработки обнаружены Git, Claude **2.1.141** и Codex **0.167.1**. На момент этой проверки Codex отклонялся из-за закреплённой **0.167.0**; теперь ограничение по номеру версии удалено. Установленная версия не изменялась. Проверки отсутствующих CLI возвращают название необходимого инструмента.
- Тесты SQLite подтверждают сохранность проектов, разговоров, настроек и обоих видов черновиков при миграции; резервная копия восстанавливается совместимой версией. Отказ миграции откатывает изменения; более новая схема отклоняется. Отдельно проверяется копия базы с WAL.
- Готовые пакеты **0.1.0 → 0.1.1** последовательно запущены после копирования в отдельное расположение, с временным `HOME` и `PATH=/usr/bin:/bin`. Пакеты содержат тот же код ядра и совместимую схему: проверялись замена приложения и миграция **4 → 5**, а не новая функциональность версии 0.1.1. Проект, пространство, разговор, сообщения, настройки и оба черновика сохранены; новых запусков в базе не появилось.
- Прошли **123** обычных теста Rust и **108** тестов интерфейса и границы SDK. Полная проверка Clippy упирается в существующие `too_many_arguments` и `needless_borrow`; при исключении этих двух диагностик остальные проверки проходят. Общий `cargo fmt --check` также обнаруживает прежние несвязанные расхождения форматирования, которые этот этап не исправляет.

Реальный ответ Claude по подписке остаётся непроверенным по ранее зафиксированной причине. Поэтому **12.1 не отмечается завершённой**: проверка запуска обоих исполнителей в установленной сборке ещё не пройдена. Условия распространения Claude также остаются неподтверждёнными согласно [матрице совместимости](executor-compatibility.md). Сквозная приёмка всех возможностей относится к этапу 13.
