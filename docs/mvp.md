# MVP ADE

## Согласованные границы

- Продукт — ADE; определения приведены в [словаре терминов](../CONTEXT.md).
- Первые пользователи — автор проекта и его команда.
- Функциональный референс — [Orca](https://www.onorca.dev/).
- Продукт разрабатывается самостоятельно, без форка Orca.
- Каждый участник запускает приложение локально на своём компьютере.
- Первая поддерживаемая ОС — macOS. Выбор стека должен сохранять возможность поддержки других ОС.
- В дальнейшем проект предполагается развивать с открытым исходным кодом.
- Особые улучшения удобства относительно Orca отложены до завершения MVP.
- Приоритеты: быстрый запуск, отзывчивый интерфейс при параллельной работе и небольшое потребление памяти. Срок разработки MVP может быть дольше ради этих качеств. По решению пользователя требования остаются качественными: численные нормативы, отдельные замеры и нагрузочный прототип не планируются.
- В MVP обязательны Claude Code и Codex. Поддерживаемый сценарий — собственные подписки пользователей; подключение через API-ключи в ADE не реализуется.
- Дополнительные жёсткие требования к бюджету и размещению данных не заданы.

## Выбранный стек

| Часть | Технология | Ответственность |
|---|---|---|
| Настольное приложение | Tauri 2 | Окна, меню, системные интеграции |
| Локальное ядро | Rust | Процессы исполнителей, терминалы, файлы и Git |
| Интерфейс | React + TypeScript | Рабочие пространства, чат, редактор и изменения |
| Хранение | SQLite | Настройки, история и состояние приложения |
| Редактор и просмотр изменений | CodeMirror 6 и @codemirror/merge | Базовое редактирование и сравнение текстов |
| Терминал | xterm.js, @xterm/addon-fit и portable-pty | Отображение терминала и управление PTY из Rust |
| Подключение Claude Code | Вспомогательный процесс на TypeScript с Claude Agent SDK | Управление установленным Claude Code; требуется среда Node.js |

Компоненты редактора и терминала и техническое направление подключения Claude Code выбраны. ADE поставляется готовым приложением со встроенной средой Node.js; Codex использует существующий штатный вход установленного CLI. Устройство описано в [архитектуре](architecture.md), последовательность работы — в [плане реализации](implementation-plan.md). Совместимость интеграций ещё предстоит подтвердить.

## Функциональные области MVP

| Область | Согласованный состав |
|---|---|
| Проекты | Открытие локальных репозиториев и папок, группы проектов, переключение между проектами |
| Рабочие пространства | Модель Orca: отдельные Git worktree и рабочие пространства общей папки, несколько сессий и вкладок внутри пространства |
| Общение | Потоковый чат, отображение действий, запросы разрешений, остановка выполнения |
| Код | Дерево файлов, вкладки, подсветка синтаксиса, поиск, ручное редактирование и просмотр изменений |
| Терминал | Интерактивные терминалы для команд, тестов и запуска приложения |
| Git | Ветки, подготовка файлов и отдельных фрагментов diff, коммиты, отправка в репозиторий, работа с конфликтами |
| Состояние | История сессий, сохранение рабочих пространств, восстановление интерфейса после перезапуска |
| Настройки | Настройка исполнителей, доступные модели и разрешения |

Встроенный браузер и отладчик в MVP не входят. Для Go и TypeScript/JavaScript редактор дополнен переходами по символам, диагностикой, автодополнением и переименованием через языковые серверы; границы и управление описаны в [навигации по коду](code-navigation.md).

## Модель организации работы

Модель принята по Orca: группа проектов объединяет отдельные проекты; у проекта могут быть несколько рабочих пространств. Git worktree относится к одному репозиторию, а пространство общей папки может охватывать несколько вложенных репозиториев. Группа проектов не создаёт для них общую ветку, общий коммит или атомарное слияние.

В рабочем пространстве могут быть несколько независимых сессий, в том числе Claude Code и Codex, а также вкладки терминалов, файлов и изменений. Единственный исполнитель на всё пространство не является ограничением модели. Отдельные Git worktree разделяют рабочие копии исходников; сессии внутри одного пространства используют общие файлы. Их параллельное выполнение разрешено с отображением активных сессий, без автоматического согласования правок между исполнителями.

Основания: [рабочие пространства Orca](https://www.onorca.dev/docs/model/worktrees), [группы проектов](https://github.com/stablyai/orca/blob/main/src/shared/project-group-types.ts), [пространства папок](https://github.com/stablyai/orca/blob/main/src/shared/folder-workspaces/folder-workspace-types.ts), [вкладки и панели](https://www.onorca.dev/docs/model/tabs-panes-splits).

## Подготовка рабочего пространства

Настройка подготовки и показ её вывода сейчас доступны только через состояние и команды ядра; отдельное окно управления пространствами убрано из интерфейса. Ранее заданная команда продолжает выполняться для новых worktree.

- Для проекта можно явно задать команду подготовки нового Git worktree.
- После создания рабочего пространства ядро запускает настроенную команду в нём и сохраняет ход выполнения.
- Если команда не задана, пространство открывается без дополнительных действий.
- При ошибке подготовки ядро сохраняет причину ошибки и созданное пространство.

## Управление сессиями и общение

- Пользователь сам создаёт рабочие пространства и запускает сессии Claude Code и Codex.
- Собственное автоматическое разбиение задач, распределение между исполнителями и сбор общего результата в MVP не входят. Штатные возможности исполнителей сохраняются.
- Общение должно соответствовать привычной работе с выбранным исполнителем: обычный диалог с его возможностями, отображением действий и запросами разрешений.
- Вложения добавляются прямо к сообщению; отдельного обязательного этапа подготовки нет. Реализованные способы передачи и границы проверки описаны в сценарии восьмого этапа ниже и [матрице совместимости](executor-compatibility.md).

### Реализованный сценарий восьмого этапа

1. Запустить приложение командой `npm run desktop` после установки зависимостей по README. В сборке разработки для Claude нужен установленный Node.js; включение среды в готовую поставку относится к этапу 12. Через «Настройки исполнителей» проверить доступность CLI: поддерживаются версии из [матрицы](executor-compatibility.md), вход выполняется штатным CLI. Отсутствие или несовместимость одного исполнителя не блокирует второго.
2. Выбрать пространство, указать исполнителя и название и нажать «Новый разговор». Разговор открывается собственной вкладкой. Можно создать Codex и Claude Code в одной папке: список и вкладки показывают исполнителя, состояние и число активных сессий. Сообщение об общих файлах напоминает, что параллельные правки пользователь согласует самостоятельно.
3. Ввести текст в поле «Сообщение» и нажать «Отправить сообщение». Текст, действия и состояние обновляются во время выполнения из сохранённой истории. При ошибке подключения уже полученный текст остаётся, а причина ошибки показана в разговоре. На экране находится до 100 сообщений и 100 событий; «Предыдущие» и «Следующие» заменяют страницу, «К последним» возвращает к текущему потоку. Открытие истории не запускает исполнителя.
4. Команды вводятся в том же поле: `$имя-навыка` для Codex и `/имя` для Claude Code в пределах матрицы этапа 1. Это не обещание поддержки всех команд терминального интерфейса CLI. Файл или изображение можно перетащить в открытый разговор либо добавить абсолютным путём кнопкой «Прикрепить файл». Файлы передаются ссылками `@путь`, изображения PNG, JPEG, GIF и WebP — штатными блоками исполнителя. Текст команды Claude идёт после изображений. Предел изображения Claude — 3 МиБ, всего сериализованного сообщения — 4 МиБ; Codex получает путь и применяет собственные ограничения изображений. Недоступный файл, неподдерживаемый формат или превышение размера показывают ошибку и сохраняют черновик.
5. При запросе разрешения проверить действие, папку и причину, затем выбрать «Разрешить один раз» либо «Отклонить запрос». Для вопросов доступны варианты и свой ответ; форма MCP использует схему исходного запроса. Решение адресуется конкретному запросу, сессии и запуску; устаревший запрос показывает ошибку и не разрешает действие другого запуска. Разрешение на всю сессию не предлагается, поскольку процесс Codex завершается после каждого хода.
6. «Остановить выполнение» вызывает штатное прерывание выбранного исполнителя. До его подтверждения показано «Ожидает остановки». Если необходимо, «Завершить процесс» завершает принадлежащее запуску дерево; другие сессии продолжают работать. Ошибка сохранения итога показана отдельно, после устранения причины можно повторить завершение для сохранения результата.
7. После завершения ввести новое сообщение и нажать «Продолжить разговор». Используется сохранённый штатный идентификатор; видимая история не отправляется повторно. Если штатные данные отсутствуют, показана ошибка, новый разговор не выдаётся за продолжение. Закрытие вкладки сохраняет разговор и выполнение; открыть его снова можно из списка пространства или «Истории разговоров» на боковой панели. После перезапуска сообщения не отправляются автоматически.
8. Неотправленный текст и пути вложений сохраняются в черновике выбранной сессии. Ошибка сохранения видна. После отправки черновик очищается только после появления сохранённого пользовательского сообщения; ошибка подготовки или запуска оставляет его доступным.
9. В «Истории разговоров» доступны в том числе разговоры архивированного или удалённого пространства. Для них открывается история без возможности выполнения. Архивированное пространство сначала нужно вернуть в активный список; для удалённого история остаётся доступной независимо от исходной папки.
10. «Удалить историю разговора» открывает отдельное подтверждение. Удаление разрешено после остановки выбранной сессии и её процессов и транзакционно удаляет только её локальные сообщения, события, черновик, настройки и вкладки. Остальные разговоры и исходные файлы сохраняются. Штатные данные CLI этим действием не удаляются.

Сценарии проверяются тестами интерфейса, SQLite и двух отдельных процессов с тестовыми реализациями протокола Codex и границы SDK Claude. Это подтверждает адресацию и передачу данных, но не реальный подписочный ответ Claude: принятое ограничение сохраняется, пункт 7.2 остаётся открытым. Проверки команд и вложений разделены по исполнителям в [матрице совместимости](executor-compatibility.md). Ручная приёмка нативного окна и готовой поставки не подменяется этими тестами.

## Ручное редактирование

- Правки исходного файла автоматически сохраняются после 1,5 секунды без ввода, при переключении или закрытии вкладки, переключении пространства и уходе из приложения. Cmd+S сохраняет немедленно. Автосохранение всегда включено.
- Несохранённый черновик сохраняется отдельно для восстановления и сам по себе не заменяет файл на диске.
- Если файл изменился снаружи при наличии несохранённых правок, редактор показывает конфликт и сохраняет обе версии до решения пользователя.

### Реализованный сценарий девятого этапа

1. Выбрать пространство и раскрыть «Файлы и поиск». Дерево загружает содержимое папок при раскрытии; «Обновить дерево» перечитывает его после внешнего создания или удаления файлов. Доступны обычные текстовые файлы UTF-8; служебные пути `.git` и символические ссылки исключены. В общей папке видны вложенные проекты, а в worktree — файлы именно этой рабочей копии.
2. Нажать имя файла. Каждый файл открывается своей вкладкой, одинаковые относительные пути разных пространств не смешиваются. CodeMirror загружает подсветку форматов из [матрицы поддержки](../EDITOR_FILE_TYPES.md) по специальному имени, расширению или известной строке `#!`. Файловые вкладки сохраняются вместе с расположением пространства; закрытие вкладки немедленно сохраняет файл, а при ошибке записи оставляет резервный черновик. Раздел «Сохранённые черновики» позволяет открыть сохранённый путь независимо от наличия файла на диске, в том числе после закрытия вкладки и перезапуска. «Обновить дерево» также перечитывает этот список.
3. Ввести текст в «Поиск в пространстве» и нажать «Найти в исходниках». Поиск буквальный, с учётом регистра, по файлам на диске; результаты содержат путь, строку и столбец. Нажатие открывает нужную рабочую копию и ставит курсор в найденное место с учётом правок черновика. Если совпадение изменено или удалено в черновике, показано сообщение без перехода к другому тексту; если найденная строка на диске уже изменилась, нужно повторить поиск. Показываются первые 200 совпадений с предложением уточнить запрос. Для поиска по текущему тексту редактора нажать «Поиск в документе» или Cmd+F, ввести запрос и использовать «Далее» и «Назад» либо Cmd+G и Shift+Cmd+G.
4. Изменить текст. На вкладке появляется точка, а текст вместе с исходной версией сразу сохраняется в SQLite. Через 1,5 секунды без ввода файл записывается автоматически; переключение вкладки или пространства, закрытие файла и потеря фокуса или скрытие окна запускают запись сразу. Клики по панелям задержку не сокращают. Cmd+S также сохраняет немедленно. Во время записи можно продолжать ввод: новые правки остаются в редакторе и попадают в следующее сохранение. Успешная запись атомарно заменяет исходник, сохраняет его права и снимает точку. Полный путь виден в подсказке вкладки; отдельной панели сохранения нет. Ошибка записи отмечается на вкладке и оставляет резервный черновик. Если черновик сохранён, вкладку и приложение можно закрыть; если не сохранён и он, закрытие блокируется. Повторить запись можно по Cmd+S или повторной попыткой закрытия.
5. Для проверки конфликта изменить файл в редакторе и до автосохранения изменить этот же файл снаружи. Открытый редактор проверяет диск раз в секунду и при возврате фокуса. Появится конфликт; ручной текст останется, автосохранение приостановится. Каждая запись дополнительно сверяет исходную версию непосредственно перед заменой файла и отклоняет внешнее изменение. Если своих несохранённых правок нет, внешнее изменение автоматически обновляет текст без конфликта.
6. Нажать «Сравнить с диском»: слева будет прочитанная внешняя версия, справа — ручной текст. Можно продолжить ручное редактирование. «Принять версию с диска» после подтверждения удаляет ручные правки из черновика без записи исходника. «Заменить файл черновиком» после отдельного подтверждения записывает ручной текст; если диск успел измениться снова, операция отклоняется до повторной проверки. Глобальная блокировка внешних программ не предоставляется.
7. Для проверки восстановления повторить правку и внешнее изменение, дождаться сохранения черновика и перезапустить приложение. Вкладка восстановит ручной текст и исходную версию отдельно от актуального файла, конфликт останется видимым. Если диск совпадает с исходной версией восстановленного черновика, автосохранение возобновится. Если вкладка была закрыта, открыть её через «Сохранённые черновики». Если файл удалён снаружи, черновик также доступен; «Восстановить удалённый файл» после подтверждения создаёт его заново, если родительская папка существует и файл не появился снова. Если внешняя версия не читается, содержит некорректный UTF-8 или нулевые байты, черновик открывается с отдельной ошибкой чтения. Принятие или замена внешней версии доступны после успешной проверки диска.
8. «Сравнить версии» открывает выбранные тексты только для чтения: исходную версию, текущий текст, файл на диске, индекс Git, `HEAD` или две отдельно выбранные ветки/коммита. «Неподготовленные изменения» сравнивают индекс с файлом на диске; «Подготовленные изменения» — `HEAD` с индексом. Отсутствующая в выбранной версии запись файла показывается пустым текстом. Для вложенного проекта выбирается репозиторий самого файла; Git выше корня пространства не используется. Просмотр не записывает файл и не меняет индекс. Подготовка изменений доступна в панели «Git».

Сценарии покрыты тестами временных Git worktree и SQLite, интерфейса вкладок и настоящих компонентов CodeMirror и MergeView. Ручная проверка нативного окна и приёмка готовой поставки остаются отдельными проверками.

### Реализованная поддержка форматов

Вся основная матрица [EDITOR_FILE_TYPES.md](../EDITOR_FILE_TYPES.md) подключена к редактору и сравнениям с диском и версиями Git. JSONC допускает комментарии и завершающие запятые; HTML и Vue подсвечивают вложенные JavaScript, TypeScript и CSS, Markdown — именованные блоки поддерживаемых языков. Неизвестный язык блока остаётся текстом. Иконки одинаковы в дереве, вкладках, поиске и Git; JSX и TSX дополнительно различаются обозначениями JS и TS. Иконки и языковые режимы входят в локальную сборку и не требуют сети.

Матрица описывает синтаксическую подсветку. Семантические возможности через LSP добавлены для Go и TypeScript/JavaScript; для остальных форматов они остаются отложенными. Специальные файлы, для которых матрица задаёт обычный текст, получают иконку назначения без обещания подсветки. Неизвестный UTF-8 текст редактируется с общими возможностями редактора. LF, CRLF и BOM сохраняются; некорректный UTF-8, нулевые байты, PDF и растровые изображения не преобразуются в редактируемый текст. SVG открывается как исходный XML, без выполнения содержимого. Иконки остальных двоичных категорий не означают встроенный просмотр.

## Работа с Git

Панель Git открывается через боковую кнопку или ⌘9 / Alt+9. Режим «Изменения» показывает файлы и сообщение коммита слева, сравнение выбранного файла — в центральной области. Режим «История» показывает ветки слева, граф коммитов и сведения о выбранном коммите справа. Выбор вложенного репозитория доступен для общей папки; родительский репозиторий обычной папки не используется.

### Изменения и коммит

- Флажок файла включает сохранённое содержимое в индекс Git. Снятие флажка исключает файл из индекса и сохраняет рабочую копию. Файл всегда показан одной строкой: частичная подготовка обозначается промежуточным состоянием флажка. Флажок набора включает либо исключает его файлы целиком; неотслеживаемые файлы показаны отдельно в группе «Новые файлы».
- Открытие полностью подготовленного файла сравнивает `HEAD` с индексом, неподготовленного или частично подготовленного — индекс с диском. Подготовленная часть доступна через меню файла. Версии можно выбирать отдельно. После подготовки файла или фрагмента сравнение обновляется на месте, сохраняя выбранный файл и прокрутку; стрелки в панели сравнения открывают соседние файлы. Сравнение подсвечивает синтаксис, выравнивает строки и позволяет переходить между изменениями. Вкладки сравнения сохраняют выбранные ревизии.
- Кнопки «+» в поле сравнения включают в индекс отдельные фрагменты рядом с изменёнными строками. Перед применением повторно проверяются показанные файл и весь индекс. Устаревший снимок отклоняется. Двоичные файлы и изменения без текстовых фрагментов включаются целиком.
- Именованные наборы помогают разделять файлы по задачам. Действия файлов и наборов доступны через контекстные меню. Двойной щелчок и F4 открывают файл в редакторе, стрелки перемещают выбор в списке. Наборы, распределение файлов и сообщение коммита сохраняются в локальном хранилище отдельно для каждого пространства и репозитория. Ошибка сохранения показывается пользователю.
- «Коммит» и ⌘Enter / Ctrl+Enter создают коммит индекса со штатными Git hooks. Неподготовленные изменения в него не включаются. «Коммит и отправка» выполняет отправку только после успешного коммита. При отказе проверки сообщение сохраняется. Флажок «Дополнить» загружает последний коммит и позволяет изменить его сообщение и подготовленное содержимое; изменение `HEAD` после выбора отклоняет операцию. История хранит последние 20 успешно использованных сообщений и позволяет вернуть их в поле коммита.
- Откат неподготовленных изменений требует подтверждения и повторной проверки снимка. Подготовленное содержимое сохраняется; неотслеживаемый файл при подтверждённом откате удаляется.

Перед чтением состояния и изменяющими операциями приложение дожидается сохранения открытых редакторов пространства. Если внешняя версия изменилась, редактор сохраняет ручной черновик и использует существующий сценарий разрешения конфликта с диском.

### История, ветки и обмен с сервером

История загружается порциями по 100 коммитов, с поиском по сообщению, автору или хешу и фильтрами ветки и автора. Метаданные читаются потоком без загрузки всей истории в память. Справа от истории показаны файлы выбранного коммита и его сообщение с автором, временем и хешем. Ширина панели регулируется разделителем. Контекстное меню коммита содержит копирование хеша, применение, отмену, создание ветки и тега; меню ветки — переключение, сравнение, слияние и удаление. Для коммита слияния изменения показаны относительно первого родителя. Файл открывается в сравнении выбранного коммита с его родителем; первый коммит сравнивается с пустым файлом. Возврат из сравнения сохраняет выбранный коммит и фильтры истории.

Доступны создание, переключение и безопасное удаление локальных веток, создание и удаление локальных тегов, сравнение веток, слияние в текущую ветку, применение и отмена выбранного коммита. Удаление ветки с неслитыми коммитами отклоняется Git. Переключение ветки выполняется сразу. Удаление, слияние, применение и отмена коммита требуют подтверждения в интерфейсе.

«Получить» выполняет `git fetch --all`, «Обновить» — `git pull --ff-only`. При расхождении веток обновление отклоняется без автоматического слияния. «Отправить» позволяет выбрать настроенный удалённый репозиторий и выполняет обычную отправку без перезаписи истории. Существующее имя отслеживаемой ветки сохраняется; для новой ветки на выбранном сервере настраивается отслеживание. Удалённые репозитории и аутентификация настраиваются штатным Git в терминале.

Раздел «Отложенные изменения» сохраняет подготовленные, неподготовленные и неотслеживаемые файлы в stash. Применение восстанавливает индекс и сохраняет запись stash; удаление выполняется отдельно с подтверждением. Перед применением и удалением проверяется, что выбранная запись не изменилась.

### Конфликты и проверки

Конфликтующие файлы выделены отдельно. Доступны наша версия, входящая версия, общий предок и рабочая копия. Результат редактируется обычным редактором, затем подготавливается кнопкой с галочкой. Конфликт исчезает только после подтверждения состоянием Git. Незавершённые слияние, применение коммита, отмена коммита и перебазирование можно продолжить либо прервать. Прерывание предупреждает о потере правок разрешения конфликтов. Интерактивный редактор перебазирования и отдельный редактор трёхстороннего слияния не реализованы.

Операции проверены на временных репозиториях и локальном удалённом репозитории: состав индекса, частичная подготовка, снятие подготовки, откат устаревшего снимка, история и её страницы, ветки и теги, сравнение веток, слияние, применение и отмена коммита, stash, получение, отправка и отказ обновления расходящихся веток. Интерфейс проверен автоматическими тестами и в браузере с тестовыми данными. Нативное окно и внешняя аутентификация сервера отдельно не проверены.

## Закрытие и восстановление

- Закрытие окна оставляет активные задачи работать в фоне.
- Полный выход через Cmd+Q предупреждает об активной работе и завершает процессы после подтверждения пользователя.
- После обычного запуска и сбоя восстанавливаются рабочие пространства, сохранённые сообщения, черновики и расположение вкладок.
- Продолжение разговора запускается явно; сохранённая история не означает восстановления прежнего процесса или отката файлов.
- Прерванная сессия обозначается как прерванная; её продолжение требует действия пользователя. Автоматического повторного выполнения команд после сбоя нет.

## Установка и настройки исполнителей

- Пользователь самостоятельно устанавливает и обновляет Claude Code и Codex.
- ADE обнаруживает установленные инструменты, проверяет наличие, версию и состояние входа и объясняет причину недоступности.
- Обязательна совместимость со штатными проектными инструкциями, навыками, MCP-серверами и настройками каждого исполнителя. Поддержку необходимо проверить отдельно для Claude Code и Codex.
- Выбор модели и разрешений доступен в ADE.
- Отдельный редактор конфигурации навыков и MCP в MVP не входит.

## Поставка приложения

- ADE поставляется готовым приложением для macOS со встроенной средой Node.js для вспомогательного процесса Claude.
- Пользователю не требуется отдельно устанавливать Node.js для самой ADE.
- Claude Code и Codex устанавливаются и обновляются пользователем самостоятельно.
- Обновление ADE в MVP выполняется вручную установкой новой версии с сохранением локальных данных.
- Для Codex используется существующий штатный вход установленного CLI; ADE проверяет состояние и подсказывает, если требуется войти. Отдельный вход через интерфейс ADE в MVP не планируется.

## Архивирование и удаление

Эти операции реализованы в ядре; кнопок архивирования, возврата и удаления в текущем интерфейсе пространств нет.

- Архивирование завершённого пространства скрывает его из активного списка, сохраняя файлы и историю с возможностью вернуться к работе.
- Перед удалением Git worktree проверяются несохранённые правки, незакоммиченные изменения и несмерженные коммиты. При наличии работы, которую можно потерять, требуется явное решение пользователя.
- Удаление ветки подтверждается отдельно от удаления рабочего пространства.
- При удалении пространства обычной папки оно убирается из ADE, а исходные файлы остаются на диске.
- Разговоры сохраняются до явного удаления истории, в том числе после удаления рабочего пространства.

### Реализованный сценарий третьего этапа

1. Нажать «Добавить папку», указать название, абсолютный путь и при необходимости группу. Репозиторий определяется по Git в выбранной папке; папка без Git открывается без создания репозитория. У группы можно задать общую папку и открыть её отдельной кнопкой. Вложенные проекты добавляются в группу отдельно, их репозитории остаются независимыми.
2. Открыть «Все проекты» и нажать «Новое пространство» у проекта с Git либо нажать плюс на верхней панели или у выбранного пространства в каталоге. Кнопка сразу открывает отдельное окно с названием проекта и тремя полями: «Название пространства», «Исходная ветка или коммит» (`HEAD` по умолчанию) и «Новая ветка» (обязательно, по умолчанию совпадает с названием пространства; можно изменить вручную). Для обычной папки создание недоступно. Нажать «Создать пространство»: Git создаёт рабочую копию от указанной исходной точки и новую ветку. С пустым именем новой ветки создание недоступно. Путь выбирается автоматически: `~/yade/workspaces/<имя папки репозитория>/<название пространства>`. Родительские папки создаются автоматически, существующая конечная папка не перезаписывается. Пробелы по краям названия убираются; название не должно равняться `.` или `..`, содержать `/`, `\` или нулевой символ.
3. Если у проекта уже задана команда подготовки, она запускается через `/bin/sh -c` в новом worktree; ядро сохраняет последние 64 КиБ вывода и итог. Без команды подготовка пропускается. Ошибка подготовки сохраняется отдельно и не удаляет пространство или созданные файлы. При открытии приложения команда повторно не запускается. Команда настройки `set_preparation_command` и состояние подготовки сохранены в ядре; элементов управления ими в текущем интерфейсе нет.
4. Команда ядра `archive_workspace` скрывает завершённое пространство из активного списка или возвращает его, сохраняя файлы, разговоры и вкладки. Активные сессии, процессы и подготовка блокируют архивирование. Отдельного списка архива и кнопок возврата в интерфейсе нет.
5. Команда ядра `inspect_workspace_deletion` возвращает черновики, изменённые, неотслеживаемые и игнорируемые файлы, коммиты вне исходной точки. `delete_workspace` требует подтверждения, при обнаруженной работе — отдельного решения о её удалении. Перед выполнением проверка повторяется; активная работа в пространстве или пересекающейся общей папке блокирует удаление. После ошибки Git остаются запись пространства и сведения о состоянии папки и регистрации worktree. Формы удаления в интерфейсе нет.
6. Удаление worktree сохраняет ветку. Команда ядра `delete_workspace_branch` отдельно требует подтверждения удаления указанной ветки. При изменении ветки после проверки операция отклоняется. Для worktree без регистрации в Git удаляется только запись приложения, оставшиеся файлы не затрагиваются.
7. Удаление пространства обычной или общей папки убирает только запись из активного интерфейса: исходная папка, вложенные репозитории, сообщения и черновики сохраняются. Связь разговоров с удалённым пространством остаётся в базе; читать их можно через «Историю разговоров» на боковой панели.

Кнопка создания недоступна при пустом названии или исходной точке. Во время создания поля и кнопки блокируются, показано «Создание пространства…». До отправки «Отмена», крестик и Escape закрывают окно без создания. При ошибке Git форма остаётся открытой с введёнными значениями и причиной ошибки. Успешное создание закрывает окно и обновляет список пространств.

Стрелка справа в поле «Исходная ветка или коммит» открывает список веток выбранного проекта с поиском. В списке есть `HEAD`, локальные ветки и известные Git удалённые ветки, например `origin/release`. Получение списка не выполняет `git fetch`: новые удалённые ветки появятся после обновления ссылок репозитория. Выбор подставляет исходную точку в поле, где также можно вручную ввести ветку, `HEAD` или хеш коммита. Escape закрывает только открытый список. При ошибке загрузки веток показывается причина; ручной ввод остаётся доступен.

Если расположение уже закреплено за другим пространством, в том числе после неудачного создания, форма сообщает: «Это расположение уже используется рабочим пространством. Укажите другое название пространства». Техническая ошибка ограничения SQLite пользователю не показывается, прежнее пространство сохраняется.

Сценарии ядра проверены на временных Git-репозиториях и SQLite, включая повторное открытие базы предыдущего этапа. Тесты интерфейса проверяют прямое открытие создания из всех трёх точек входа и недоступность создания для обычной папки. Размеры формы сверены в браузере с окном нового чата при масштабах 100%, 125% и 150%; узкое окно проверено при ширине 390 пикселей и масштабе 125%. Работа формы в нативном окне macOS отдельно не проверялась; сквозная приёмка в готовой поставке остаётся этапом 13.

## Интеграции: проверенные ориентиры

- Для Codex выбран локальный `app-server` с событиями, разрешениями и продолжением сессий. По решению пользователя MVP использует текущий штатный вход установленного CLI. Его работу с конкретными версиями и подписками первых пользователей ещё необходимо подтвердить; наличие альтернативного Sign in with ChatGPT не означает автоматической замены выбранного сценария. Источники: [App Server](https://learn.chatgpt.com/docs/app-server), [Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source).
- Для Claude Code описан запуск неизменённого CLI со штатным входом пользователя по подписке. ADE не должна подменять этот вход, копировать токены или изменять встроенные способы аутентификации CLI. Для полноценного чата выбран отдельный процесс на TypeScript с официальным Claude Agent SDK, запускающим установленный CLI. Среда Node.js поставляется внутри ADE. Соответствие конкретной схемы подписочному сценарию и полноту совместимости ещё необходимо установить. Источники: [условия подключения Claude Code](https://code.claude.com/docs/en/legal-and-compliance), [обзор SDK](https://code.claude.com/docs/en/agent-sdk/overview).

Выбор интерфейсов подключения подтверждён сверкой с исходниками Orca; проверенная ревизия и точные ссылки приведены в [архитектуре](architecture.md). Реальные входы, сессии, восстановление и потребление ресурсов не проверялись.

## Предлагаемые функциональные критерии готовности

- ADE обнаруживает установленные Claude Code и Codex, объясняет недоступность и позволяет работать через личные подписки без ввода API-ключей в ADE.
- Для каждого исполнителя работают отправка сообщения, потоковый ответ, запрос разрешения, остановка и явное продолжение сохранённой сессии; отдельно проверяется наследование инструкций, навыков, MCP и настроек.
- Создание нескольких Git worktree и ошибки создания отражаются в интерфейсе без ложного статуса успешного завершения. Ранее настроенная команда подготовки выполняется ядром, её вывод и ошибки сохраняются в состоянии пространства.
- Несохранённые ручные правки сохраняются после перезапуска; внешнее изменение открытого файла не уничтожает их.
- Подготовка файлов и отдельных фрагментов diff затрагивает только выбранные изменения. Git-операции отображают фактический результат и ошибки; неуспешная операция не скрывает оставшиеся изменения.
- Закрытие окна сохраняет выполнение, а полный выход предупреждает об активной работе и завершает принадлежащие приложению процессы.
- После сбоя восстанавливаются сохранённые сообщения, черновики и вкладки; команды не запускаются повторно автоматически.
- Архивирование сохраняет файлы и историю; удаление пространства папки не удаляет её файлы; история разговоров сохраняется после удаления пространства до отдельного решения пользователя.

- Готовое приложение запускается со встроенной средой Node.js и обнаруживает отдельно установленные CLI. Ручная установка новой версии сохраняет локальные данные.

Это сценарии функциональной проверки для будущей реализации. Они не выполнены и не включают замеры производительности.

## Что требует подтверждения

- Фактическая работа обоих исполнителей через подписки в выбранных интерфейсах подключения.
- Соответствие встраивания Claude SDK условиям использования подписки и отсутствие подмены штатного входа.
- Совместимость версий исполнителей и покрытие привычных возможностей в чате.
- Работоспособность готовой сборки, восстановление и сохранность данных по функциональным критериям выше.

Подписочные интеграции и применимость условий их встраивания проверяются до основной реализации интерфейса согласно [плану](implementation-plan.md). Сведения из документации не считаются результатом этих проверок.

Остальные возможности Orca не считаются автоматически включёнными в MVP.
