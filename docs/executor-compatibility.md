# Совместимость исполнителей

Дата проверки: 10 ноября 2026 года. Первый этап `build-local-ade-mvp`; результаты относятся к локальному эксперименту, а не к готовому приложению.

Уточнение пользователя: локальный Claude Code недоступен, поэтому его подключение реализуется по флоу Orca и проверяется на границе SDK. Повторный вход и реальный подписочный запуск на этой машине не требуются для продолжения разработки. Ниже результаты реальных запусков отделены от локальных тестов и сверки исходников; обязательные возможности готового приложения сохраняются.

## Обнаружение и штатный вход

Команда проверки: `node experiments/executor-compatibility/check-cli.mjs`. Используется временная рабочая папка; вывод статуса входа фильтруется до признака доступности, способа входа и типа подписки. Файлы токенов и Keychain проверочный сценарий не читает.

| Сценарий | Codex | Claude Code |
|---|---|---|
| Установленная версия | `codex-cli 0.167.0` | `2.1.141` |
| Текущий штатный вход | ChatGPT, код выхода 0 | claude.ai, подписка Pro, код выхода 0 |
| Отсутствующий CLI | Пустой `PATH`: `ENOENT` | Пустой `PATH`: `ENOENT` |
| Необходимость входа | Временное хранилище `ephemeral`: вход отсутствует, код выхода 1 | Новая папка `CLAUDE_CONFIG_DIR`: `loggedIn: false`, `authMethod: none`, код выхода 1 |

Проверка отсутствующего входа не выполняет `logout` и не меняет существующий профиль. Статус входа сам по себе не доказывает доступность ответа по подписке.

## Codex app-server из Rust

Минимальный сценарий находится в `experiments/executor-compatibility/codex`. Зависимость `serde_json` закреплена в `Cargo.lock`; проверена сборка Rust `1.99.1`.

Запуск: `cargo run --locked --manifest-path experiments/executor-compatibility/codex/Cargo.toml -- <папка> <сообщение> [идентификатор разговора]`.

На Codex `0.167.0` подтверждены `initialize` / `initialized`, `account/read`, `thread/start`, `turn/start`, события `item/agentMessage/delta` и `turn/completed`. Тип учётной записи — `chatgpt`; получен ответ `YADE_STREAM_OK`, четыре потоковых события, итог `completed` без ошибки.

Отрицательные проверки: несуществующий исполняемый файл даёт `spawn_failed`; завершившийся процесс без протокольного ответа — `connection_closed`. Обе проверки завершились кодом 1. Проверка адресации разрешений отклоняет запрос другого запуска.

С `approvalPolicy: untrusted`, `approvalsReviewer: user` и `sandbox: read-only` получен `item/commandExecution/requestApproval` на команду `touch` во временной папке. Ответ `accept` создал файл, `decline` оставил его отсутствующим; оба запуска завершились `completed`. Решение привязано к исходным `threadId`, `turnId` и идентификатору запроса.

Разговор `01a1c5cb-ee84-7533-8049-796710aac617` продолжен новым процессом через `thread/resume`: без передачи истории повторён прежний ответ `YADE_STREAM_OK`. В следующем запуске вызов `turn/interrupt` прервал команду `sleep`, получен итог `interrupted`. Последующее продолжение того же разговора вернуло `RESUME_OK` без нового выполнения команды.

Точная схема получена из установленного CLI командой `codex app-server generate-json-schema`. Документация: [App Server](https://learn.chatgpt.com/docs/app-server).

Сравнение app-server и обычного `codex exec` на одном тестовом проекте подтвердило чтение уникальной строки файла, проектный навык `$compatibility-probe`, маркер инструкции `AGENTS.md`, вызов `ping` локального MCP и распознавание одноцветного PNG `64×32`. В обоих ответах совпали уникальные строки файла и MCP, маркеры инструкций и навыка и цвет `red`. Пользовательские файлы настроек не изменялись. Сценарий повторения — `codex/check-compatibility.mjs` в каталоге эксперимента.

`config/read` подтвердил активный пользовательский слой и отключённый проектный слой с конкретной причиной: репозиторий не имеет сохранённого штатного доверия. Доверие родительскому каталогу и передача `projects.<путь>.trust_level` через `-c` не включили проектный слой. Поэтому для положительной проверки обмена MCP тестовый сервер передан явными параметрами запуска; этот результат не считается подтверждением загрузки MCP из проектного файла. Параметр `model_reasoning_effort: low` также проверен как явное переопределение запуска.

Загрузка проектного MCP и настроек в доверенном проекте в этом запуске не подтверждена. Для будущего приложения доступна причина отключения через `config/read`; её нужно показывать пользователю, сохраняя штатное управление доверием Codex. Это требование к окружению и диагностике, а не автоматическое изменение доверия. Документация описывает загрузку проектных слоёв только для доверенных проектов: [конфигурация Codex](https://learn.chatgpt.com/docs/config-file/config-advanced).

## Claude Code через SDK TypeScript

Создан сценарий `experiments/executor-compatibility/claude/probe.ts` с SDK `0.2.141`, Node.js `26.8.1`, TypeScript `5.9.3`. Версии зависимостей закреплены в `package-lock.json`. Установленный CLI передан через `pathToClaudeCodeExecutable`, рабочая папка — через `cwd`; включены `systemPrompt: claude_code`, источники `user`, `project`, `local` и потоковые сообщения. Переменные API-ключей и прямой передачи OAuth-токена из окружения дочернего процесса удалены.

Реальный запуск подтвердил инициализацию CLI `2.1.141` в выбранной временной папке, `apiKeySource: none`, модель `claude-sonnet-4-6` и штатный `session_id`. Запрос завершился `is_error: true`, `api_error_status: 401`, текстом `OAuth access token is invalid`; потоковых событий нет. Поле `subtype: success` при этом присутствует и не считается успехом: сценарий проверяет также `is_error` и завершился кодом 1.

Обычный запуск неизменённого CLI через `claude -p` в той же папке без SDK воспроизвёл ту же ошибку 401. Это результат предыдущей попытки. Пользователь подтвердил недоступность локального Claude и выбрал реализацию флоу Orca без повторных попыток восстановить вход здесь. Реальные сценарии Claude остаются непроверенными; локальные тесты не объявляются результатом подписочного запуска.

Текущая реализация сохраняет выбранный штатный `CLAUDE_CONFIG_DIR`, рабочее окружение и прокси, удаляет унаследованные переменные API-ключей и авторизации и обозначает приложение как `CLAUDE_CODE_ENTRYPOINT: yade`. Вызов `query()` получает установленный CLI, `cwd`, инструкции `claude_code`, настройки `user`, `project`, `local`, поток нового сообщения, обработчик разрешений и исходный `resume` при продолжении. Собственное хранилище входа, извлечение токенов и повторная отправка истории не используются.

Восемь локальных тестов на границе SDK подтверждают:

- передачу пути CLI, папки, профиля, настроек и сообщения, сохранность исходного окружения и публикацию частичного ответа до результата;
- обработку `is_error: true` с `subtype: success`, разрыва соединения и ошибки транспорта без ложного успеха;
- продолжение по исходному идентификатору с одним новым сообщением и отклонение несовпадающего идентификатора;
- разрешение и отказ с исходным `toolUseID`, запрет разрешения отменённого запроса;
- вызов `interrupt()` только у выбранной сессии и ожидание результата с `terminal_reason: aborted_tools` перед фиксацией прерывания;
- передачу текста команды, ссылки на файл и блока изображения без отдельной подготовки. Как в Orca, изображения идут первыми, текстовые части объединяются в последний блок, из которого Claude раскрывает команду. Это проверка передачи в SDK, а не выполнения команды или распознавания изображения реальным Claude.

В опубликованном `sdk.d.ts` версии `0.2.141` имеются отсутствующие определения типов, включая `RemoteControlHandle` и `SDKControlChannelEnableRequest`. Собственный код проверяется в строгом режиме TypeScript с `skipLibCheck`; декларации зависимости этим запуском не проверяются.

## Схема подключения Orca

Проверена ревизия `643411cfa3ab20b6cb5c22f2b18d418346e22938`:

- Вход выполняет штатный CLI командой `claude auth login --claudeai`; в записи учётной записи указан `subscription-oauth`. Источники: [вход](https://github.com/stablyai/orca/blob/643411cfa3ab20b6cb5c22f2b18d418346e22938/src/main/claude-accounts/claude-login-session.ts#L69), [тип авторизации](https://github.com/stablyai/orca/blob/643411cfa3ab20b6cb5c22f2b18d418346e22938/src/main/claude-accounts/claude-account-registration.ts#L124).
- Во встроенном чате вызывается `query()` официального SDK с путём установленного CLI, рабочей папкой и окружением. Выбранная учётная запись передаётся через `CLAUDE_CONFIG_DIR`; без отдельного профиля используется штатное расположение пользователя. Источники: [вызов SDK](https://github.com/stablyai/orca/blob/643411cfa3ab20b6cb5c22f2b18d418346e22938/src/main/claude/claude-stream-json-connection.ts#L121), [выбор профиля](https://github.com/stablyai/orca/blob/643411cfa3ab20b6cb5c22f2b18d418346e22938/src/main/claude-accounts/claude-profile-router.ts#L261).
- Для отображения лимитов Orca отдельно читает OAuth-токен из Keychain или `.credentials.json` и запрашивает `/api/oauth/usage`. Это отдельная от запуска разговора функция; в текущий эксперимент она не входит. Источники: [чтение](https://github.com/stablyai/orca/blob/643411cfa3ab20b6cb5c22f2b18d418346e22938/src/main/rate-limits/providers/claude/claude-oauth-credentials.ts#L97), [запрос](https://github.com/stablyai/orca/blob/643411cfa3ab20b6cb5c22f2b18d418346e22938/src/main/rate-limits/providers/claude/claude-oauth-usage-request.ts#L83).
- Каталог привычных команд и навыков приходит из штатной инициализации CLI; Orca учитывает `slash_commands`, `skills` и изменения каталога. Источник: [каталог](https://github.com/stablyai/orca/blob/643411cfa3ab20b6cb5c22f2b18d418346e22938/src/main/claude/claude-slash-command-catalog.ts).
- Изображения преобразуются в штатный блок `image` с источником `base64` или URL; текстовые части объединяются и идут последними, чтобы сохранить раскрытие команд Claude. Источник: [сборка сообщения](https://github.com/stablyai/orca/blob/643411cfa3ab20b6cb5c22f2b18d418346e22938/src/main/claude/structured/claude-structured-dispatch-content.ts).

Код подтверждает способ подключения. Подтверждение отдельного разрешения Anthropic в просмотренных материалах не найдено; это не доказывает его отсутствие.

## Условия встраивания Claude

[Обзор SDK](https://code.claude.com/docs/en/agent-sdk/overview) требует предварительного разрешения Anthropic для предоставления входа claude.ai и лимитов подписки в стороннем продукте через SDK. [Условия Claude Code](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use) отдельно допускают вход пользователя по своей подписке в неизменённый CLI, в том числе на сторонней платформе. Применимость этого исключения к распространению выбранной схемы с SDK пока не подтверждена. Технический запуск не будет считаться подтверждением условий.

## Переход к этапу 2

Первый этап завершает проверку механизма подключения и фиксирует границы доказательств. По уточнению пользователя можно продолжать реализацию по флоу Orca без восстановления локального Claude. Для следующего этапа основа приложения не требует нового способа авторизации или замены SDK. Проектные настройки Codex должны учитывать его штатное доверие и показывать причину отключения.

Это решение о продолжении разработки, а не приёмка готового приложения: реальная совместимость Claude, положительная загрузка проектного MCP Codex в доверенном проекте, полный набор привычных команд и применимость условий распространения Claude остаются неподтверждёнными. Их нельзя объявлять реализованными по результатам этого эксперимента; реальные проверки нужны до приёмки соответствующих возможностей. API-ключи вместо подписок не используются; требования готового приложения не сокращены.

Команды повторения сборки, тестов и реальных сценариев приведены в [инструкции](../experiments/executor-compatibility/README.md).

## Реализованный пятый этап

В приложении доступна кнопка «Настройки исполнителей». Она показывает путь, версию и статус штатного входа каждого CLI отдельно. Ограничений по номеру версии Codex и Claude Code нет: версия сохраняется для диагностики и не блокирует запуск. Ошибки входа и протокола отображаются при проверке и запуске. Приведённые в отчёте версии обозначают окружение выполненных проверок. Поиск использует `PATH`, `~/.local/bin`, `~/.cargo/bin`, `~/.npm-global/bin` и стандартные каталоги Homebrew и системы. Отсутствие одного инструмента не блокирует настройки другого.

Вход выполняется пользователем в штатном терминале: `codex login` или `claude auth login --claudeai`. Приложение вызывает только `codex login status` или `claude auth status --json`, отбрасывает сведения об учётной записи и не читает файлы токенов или Keychain. Переменные прямой передачи API-ключей и токенов исключены из окружения подключения. `CODEX_HOME`, `CLAUDE_CONFIG_DIR` и прокси сохраняются. Найденный штатный вход не доказывает, что подписка позволит получить следующий ответ: прежняя ошибка Claude 401 этим этапом не опровергнута.

После выбора пространства можно настроить каждого исполнителя отдельно. При открытой вкладке сохранённой сессии доступна её собственная область настроек; изменение параметров выполняющейся сессии запрещено. Параметры пространства используются, пока у сессии нет собственного сохранённого выбора. Значение «Штатная настройка исполнителя» не передаёт переопределение модели или разрешений. Настройки сохраняются в существующей таблице SQLite `settings`; штатные конфигурационные файлы CLI не изменяются.

Для Codex Rust запускает короткую проверку app-server в папке пространства: `initialize`, `account/read`, `config/read`, `model/list` и `thread/start` с `ephemeral: true`. Отправки `turn/start` нет. Каталог моделей приходит из CLI; политика запросов и режим песочницы проверяются по протоколу установленной версии. Явные параметры сохраняются только после успешного ответа и сверки принятых значений. Причины отключённых слоёв из `config/read` показаны на экране; доверие проекту автоматически не меняется. Инструкции, навыки и MCP остаются на штатных источниках из матрицы первого этапа. Основа протокола: [App Server](https://learn.chatgpt.com/docs/app-server).

Для Claude используется SDK `0.2.141` из зависимостей приложения. Проверка получает каталог через `supportedModels()` и проверяет явные параметры через `setModel()` и `setPermissionMode()`. Каталог строится в домашней папке с пользовательским источником настроек. Хуки и MCP из файлов отключены. Во входной поток сообщения не отправляются; проверка закрывает своё подключение. Источники инструкций описаны в [документации SDK](https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts). Каталог не гарантирует право подписки на ответ выбранной модели. В разработке используется локальный Node.js; готовая `.app` этапа 12 включает собственную среду и служебные файлы, как описано в [инструкции поставки](desktop-delivery.md).

Панель «Параметры диалога» рядом с отправкой сообщения сохраняет выбор для текущего разговора: модель, режим «Выполнение»/«План», усилия рассуждения, быстрый режим и доступы. Допустимые усилия и поддержка ускорения берутся из каталога выбранной модели; смена модели сбрасывает эти два переопределения. Пока проверка и сохранение не завершены, отправка сообщения заблокирована; при отказе восстанавливаются прежние значения. Во время выполнения параметры доступны только для чтения. Codex получает усилия через `config.model_reasoning_effort`, ускорение через `serviceTier`, а режим через `turn/start.collaborationMode` с включённым `experimentalApi`. Claude получает `effort`, `settings.fastMode` и `permissionMode`; режим планирования временно перекрывает выбранный режим разрешений. Отдельный режим «Вопрос» недоступен. Разделы «Инструменты» и «Контекст» поясняют использование штатных источников и не меняют их. Основания: [протокол Codex](https://learn.chatgpt.com/docs/app-server) и [параметры SDK Claude](https://code.claude.com/docs/en/agent-sdk/typescript).

Проверки пятого этапа:

- Локально обнаружены обе проверенные версии и штатный вход. Тесты с временным CLI отдельно проверяют отсутствие инструмента, необходимость входа и допуск старых, новых и предварительных версий обоих исполнителей.
- Реальная инициализация Codex без сообщения вернула восемь моделей; явная модель, политика и песочница приняты, неизвестная модель отклонена. Проверка требует записи служебного состояния Codex в его штатную папку, поэтому запускалась вне песочницы. Она не повторяет сценарии ответа, навыка и MCP первого этапа.
- Тесты Rust проверяют границы пространства, исполнителя и сессии, сохранение после открытия базы, наследование параметров, запрет изменения активного запуска, причины отключённой конфигурации и отказ CLI.
- Локальные тесты границы SDK проверяют штатный профиль, инструкции и источники настроек Claude, отсутствие неявных переопределений, передачу явного выбора и ошибку отклонённого значения. Реальная подписочная проверка Claude не выполнялась повторно.
- Тесты интерфейса подтверждают адресацию выбранной сессии, показ ошибки без ложного успешного статуса и настройку Claude при отсутствующем Codex.

Это обнаружение и проверка параметров для следующих запусков. Постоянные подключения, отправка сообщений и создание разговоров относятся к этапам 6–8; экран не объявляет проверочное подключение выполняющейся сессией.

## Реализованный шестой этап

Дата проверки: 11 ноября 2026 года. Подключение ядра проверено с установленным Codex `0.167.0` и его схемой app-server v2, полученной через `codex app-server generate-json-schema`. Описание обмена: [App Server](https://learn.chatgpt.com/docs/app-server). Экран чата остаётся отдельной задачей этапа 8.

`src-tauri/src/codex_rpc.rs` разбирает JSON по строкам stdio, включая пакеты, разбитые между чтениями и внутри символа UTF-8. Ответы сопоставляются с исходными запросами независимо от порядка прихода. Очередь чтения ограничена 32 пакетами, очередь записи — 16, отдельный пакет — 8 МиБ. Запись выполняется отдельным потоком; постановка в очередь не блокирует обработку управления запуском, поэтому завершение процесса доступно и при зависшем stdin. Заполнение очереди записи, превышение размера, повреждённый пакет, обрыв строки, закрытие соединения, неизвестный ответ, ошибка записи и отсутствие ответа на RPC в течение 30 секунд завершаются ошибкой. Чтение и работа подключения выполняются вне потока интерфейса. Диагностика stderr не смешивается с протоколом и не накапливается в памяти.

`src-tauri/src/codex.rs` запускает установленный `codex app-server` в папке пространства, со штатным профилем и отфильтрованным окружением из этапа 5. Проверяются версия, подписочный вход через `account/read`, поставщик из `config/read` и принятые явные параметры модели и разрешений. Причины отключённых слоёв конфигурации сохраняются как предупреждения; доверие проекту не меняется.

После `initialize` / `initialized` новый разговор создаётся через `thread/start`, существующий — через `thread/resume` с сохранённым `external_id`. Несовпадающий идентификатор или ошибка продолжения не приводят к `thread/start`. В `turn/start` передаётся только новое сообщение в штатном формате `input`; видимая история не отправляется заново. Новый процесс обслуживает один запуск, после его подтверждённого итога освобождается вместе с дочерними процессами. Следующее явное сообщение продолжает тот же штатный разговор новым процессом.

Команды Tauri: `create_codex_session`, `start_codex_turn`, `reply_codex_request`, `interrupt_codex_turn`, `stop_codex_process`, `session_messages`, `session_events`. Запуск возвращает контекст пространства, сессии и запуска. События поступают через `run-event` с тем же контекстом и сохранённым порядковым номером; история читается порциями до 100 записей. Схема SQLite не менялась.

Пользовательское сообщение, части ответа, итоговое сообщение, действия, вывод, предупреждения и запросы сохраняются до публикации. Части одного ответа обновляют одну запись сообщения; итоговый текст не дублирует поток. Состояния различают `starting`, `running`, `waiting`, `stopping`, `completed`, `failed`, `error` и `interrupted`. Запрос ввода с `isBlocking: false` сохраняется без объявления остановки выполнения. Ошибка процесса или соединения сохраняет полученный текст и не становится успешным завершением. Если запись не удалась, отдельный сигнал `save_error` имеет `sequence: 0` и `saved: false`, поэтому не выдаётся за сохранённое событие.

Разрешения команд и файлов, запрос дополнительных прав, пользовательские вопросы и запросы MCP сохраняют исходные `threadId`, `turnId` и идентификатор запроса. Самостоятельный запрос `mcpServer/elicitation/request` с `turnId: null` допускается до начала первого хода при совпадении разговора и запуска. Ответ проверяется по контексту и ожидаемой форме; дополнительные права могут быть только подмножеством запрошенных. Неизвестные запросы отклоняются. После `serverRequest/resolved`, завершения или остановки прежний ответ не применяется. Решение для одной сессии не снимает ожидание другой, даже при совпадении идентификаторов запросов.

Разрешение на всю сессию не поддерживается: процесс завершается после каждого хода, поэтому штатный кэш разрешений между ходами не сохраняется. Ответы `acceptForSession` и `scope: "session"` отклоняются с явной ошибкой, запрос остаётся ожидающим. Доступны разовое разрешение, отказ и отмена; дополнительные права можно выдать без `scope` или со `scope: "turn"`.

`interrupt_codex_turn` направляет `turn/interrupt` и оставляет состояние `stopping` до штатного итога. Отправка запроса и ответ на RPC сами по себе не означают прерывания. Явное завершение процесса подтверждается после остановки его дерева и сохранения результата. Если сохранить остановку или итог не удалось, повторное завершение позволяет повторить запись, не отправляя сигнал уже освобождённому PID. Открытие базы не запускает сохранённые разговоры.

Проверки шестого этапа:

- Локальные тесты транспорта и временного процесса: разбиение пакетов, перемешанные ответы, повреждённые данные, закрытие потока, переполнение очереди записи, учёт и освобождение процесса, остановка при большом сообщении и не читающем stdin процессе.
- Тесты последовательностей: порядок потоковых сообщений и действий, отсутствие дублирования текста, сохранение до публикации, частичный ответ при ошибке, отказ SQLite и повторная запись итога.
- Тесты управления: два параллельных запроса с одинаковым идентификатором, чужой контекст, устаревший ответ после нового запуска, снятый запрос, отказ, формы ввода и дополнительных прав, запрос MCP до начала хода, запрет сессионных решений с сохранением ожидания, ожидание подтверждения прерывания и независимость процессов.
- Реальный `local_codex_conversation_survives_restart`: короткий ответ, повторное открытие базы и продолжение новым процессом восстановили уникальную контрольную строку без передачи истории; штатный идентификатор сохранился.
- Реальный `local_codex_interrupt_is_confirmed_and_other_session_remains_available`: команда `/bin/sleep 120` прервана через `turn/interrupt` с итогом `interrupted`, второй разговор вернул `INDEPENDENT_OK` с итогом `completed`, учтённых процессов не осталось.

Повторение локальных тестов: `cargo test --locked --manifest-path src-tauri/Cargo.toml codex -- --nocapture`. Реальные проверки запускаются отдельно: `cargo test --locked --manifest-path src-tauri/Cargo.toml local_codex_ -- --ignored --nocapture`. Им нужен доступ Codex к его штатной папке вне песочницы; они отправляют сообщения по существующей подписке во временных рабочих папках. Файлы токенов не читаются. Реальные проверки Claude и ручной прогон интерфейса этим этапом не выполнялись.

## Реализация седьмого этапа

Дата локальной проверки: 11 ноября 2026 года. Добавлены `executors/claude-bridge.ts` и обработчик `src-tauri/src/claude.rs`. Используется уже закреплённый SDK `0.2.141`; версия CLI `2.1.141` относится к окружению проверки, ограничений по номеру версии CLI нет. Вспомогательный процесс проверен на Node.js `26.8.1`, включая штатное выполнение TypeScript без отдельного загрузчика. В режиме разработки Node.js обнаруживается на машине; готовая сборка этапа 12 запускает включённую среду из ресурсов `.app`.

Команды Tauri: `create_claude_session`, `start_claude_turn`, `reply_claude_request`, `interrupt_claude_turn`, `stop_claude_process`. История и события читаются общими `session_messages` и `session_events`, публикуются через `run-event`. Каждому запуску принадлежит отдельный процесс SDK и его дерево; существующий реестр проверяет принадлежность перед завершением. Схема SQLite и интерфейс разговоров не менялись; последний относится к этапу 8.

Обмен Rust и TypeScript использует JSON по строкам с идентификаторами запросов. В каждом ответе и событии проверяется контекст пространства, сессии и запуска. Транспорт ограничивает пакет восемью МиБ и очереди Rust — 16 пакетами на запись и 32 на чтение; запись TypeScript учитывает обратное давление stdout. Невалидный JSON, повреждённый UTF-8, оборванный пакет, закрытие потока и ответ на неизвестный запрос приводят к ошибке. Диагностика SDK направляется в stderr, который Rust отдельно вычитывает; она не попадает в протокол или историю.

Первый запуск разговора требует подтверждения доверия к пространству в системном диалоге. Доверие действует для выбранного пространства и его пути до выхода из Yade. После подтверждения путь CLI, `cwd`, модель и режим разрешений передаются через `launchOptions` со штатным профилем, прокси, инструкциями `claude_code` и источниками `user`, `project`, `local`. Фоновый запрос названия запускается в домашней папке с отключёнными настройками из файлов, хуками и MCP. API-ключи и прямые токены исключаются из окружения. Приложение не читает хранилище входа и не восстанавливает авторизацию автоматически.

`system/init` сохраняет штатный `session_id` в `sessions.external_id`. Следующее явное сообщение запускает новый процесс с `resume` и только новым сообщением. До продолжения SDK `getSessionInfo` проверяет наличие штатных данных разговора в папке проекта. Их отсутствие или несовпадающий идентификатор дают ошибку, без подмены новым разговором. Открытие базы не запускает сохранённые сессии.

Части текста, итоговые сообщения, действия, запросы и состояния сохраняются до публикации. Завершённые текстовые блоки с общим `message.id` объединяются по порядку в одну запись с их потоком, без потери предыдущего блока и дублирования текста; порядок событий соответствует [документации SDK](https://code.claude.com/docs/en/agent-sdk/streaming-output). Ошибка транспорта сохраняет уже полученный текст. `subtype: success` вместе с `is_error: true` не означает успеха: в том числе сохраняются причина и статус ошибки авторизации. После неудачного сохранения публикуется `save_error` с `sequence: 0`; явное повторное завершение позволяет сохранить итог после устранения ошибки базы.

Разрешения `canUseTool`, вопросы `AskUserQuestion` и ввод MCP через `onElicitation` получают отдельный идентификатор запроса. Ответ проверяется и в Rust, и во вспомогательном процессе. Для инструмента разрешение использует исходный ввод и `toolUseID`; для вопросов добавляются ответы на исходные вопросы. Изменять команду или выдавать постоянные права через ответ нельзя. Отказ не превращается в разрешение. Отмена SDK, окончание и остановка запуска снимают ожидание; чужие и устаревшие ответы отклоняются.

`interrupt_claude_turn` вызывает SDK `interrupt()` и переводит запуск в `stopping`. Ответ на команду управления сам по себе не завершает запуск: `interrupted` устанавливается по штатному результату с `terminal_reason: aborted_streaming` либо `aborted_tools`. `stop_claude_process` принудительно завершает только принадлежащее запуску дерево и подтверждает итог после очистки. Если процесс сам завершился между обходом дерева и сигналом группе, реестр повторно проверяет фактическое завершение перед освобождением дескриптора.

Локально подтверждены девятью тестами границы SDK и девятью интеграционными тестами Rust: передача параметров и сообщения, поток и сохранение, продолжение после повторного открытия базы, отсутствие данных и несовпадение разговора, разрешения двух сессий, отказ, вопросы, MCP, отмена, устаревший ответ, подтверждённое прерывание, очистка дочерних процессов, заблокированный ввод, ошибки протокола, авторизации и повторная запись итога. Интеграционные тесты запускают настоящий процесс Node.js с подставной реализацией границы SDK; это не подписочные ответы Claude.

Повторение: `node --test executors/claude-bridge.test.mjs` и `cargo test --locked --manifest-path src-tauri/Cargo.toml claude -- --nocapture`. Проверкам управления процессами нужен доступ macOS к их дереву вне песочницы. Типы вспомогательного процесса проверяются командой `npx tsc -p executors/tsconfig.json`, включённой также в `npm run build`.

С учётом предупреждения пользователя реальная подписочная проверка на этой машине не выполнялась повторно. Добавлен отдельно запускаемый тест `local_claude_conversation_survives_restart`: `cargo test --locked --manifest-path src-tauri/Cargo.toml local_claude_ -- --ignored --nocapture`. Он отправляет два сообщения во временном проекте через существующий вход, проверяет ответ и продолжение после повторного открытия базы; обычно пропускается. **Пункт 7.2 остаётся открытым по критерию реального подписочного ответа и наследования конфигурации**, хотя путь запуска реализован и проверен локально. Совместимость личной подписки, реальное применение инструкций, навыков и MCP, а также условия распространения не объявляются подтверждёнными. Ручная проверка интерфейса не выполнялась.

## Реализованный восьмой этап

Дата проверки: 11 ноября 2026 года. В интерфейсе доступны создание разговоров и вкладки обоих исполнителей, поток сохранённых сообщений и действий, разрешения, вопросы, остановка и явное продолжение. Последние сообщения и события читаются отдельными страницами до 100 записей. Актуальные запросы извлекаются независимо от страницы и сохраняют исходный контекст запуска. Закрытие представления не вызывает остановку. Истории архивированных и удалённых пространств доступны для чтения, выбранная локальная история удаляется отдельным подтверждением. Сценарии приведены в [MVP](mvp.md#реализованный-сценарий-восьмого-этапа).

Сборка сообщения сохраняет команды в тексте: `$имя-навыка` Codex и `/имя` Claude в пределах матрицы первого этапа. Обычный файл передаётся ссылкой на абсолютный путь, изображения PNG, JPEG, GIF и WebP — через `localImage` Codex или `image/base64` Claude. Для Claude изображения идут первыми, объединённый текст команды — последним. Путь можно добавить прямо к сообщению или перетащить из Finder. Перед запуском проверяются доступность файла, формат и размер изображения; ошибка сохраняет черновик и не запускает процесс. Для base64 используется уже имеющаяся в дереве зависимостей Rust библиотека, без загрузки новой версии.

Локальные тесты подтверждают страницы истории, актуальность запросов, транзакционный отказ удаления, сохранение других разговоров, запрет выполнения в удалённом пространстве и оба формата вложений. Интеграционный тест запускает одновременно два отдельных процесса: протокол Codex и границу SDK Claude. Частичные ответы читаются до завершения; оба работают в одной папке, решение Codex сохраняет ожидание Claude, закрытие представлений сохраняет оба процесса. В журнале SDK проверены рабочая папка, изображение, текст команды и отказ пользователя. Это не реальный подписочный ответ Claude.

Реальная проверка `local_conversation_input_commands_and_attachments` на Codex `0.167.0` подтвердила новый путь сборки сообщения: навык `$compatibility-probe` добавил свой маркер, файл с пробелами в абсолютном пути вернул уникальную строку, приложенный PNG распознан как `red`. Поскольку установленный CLI уже обновился до `0.167.1`, для теста `0.167.0` запущен через `npm exec` из временного кэша. Установленный CLI и пользовательские настройки не изменялись. На момент проверки `0.167.1` отклонялась по номеру версии; теперь это ограничение удалено. Успешный тест `0.167.0` подтверждает реальный сценарий только для этой версии.

Повторение реального теста с установленной проверенной версией: `cargo test --locked --manifest-path src-tauri/Cargo.toml local_conversation_input_commands_and_attachments -- --ignored --nocapture`. Тест использует штатную подписку и временный проект, обычно пропускается. Полный набор команд терминального интерфейса, реальная совместимость Claude и ручная приёмка нативного окна этим этапом не объявляются проверенными.
