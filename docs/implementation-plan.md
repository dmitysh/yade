# План реализации MVP

План основан на [требованиях](mvp.md) и [архитектуре](architecture.md). Основа локального приложения реализована на этапе 2; команды запуска и границы проверенного результата приведены в [README](../README.md). Остальные разделы описывают дальнейшую работу.

## 1. Подтвердить подключение исполнителей через подписки

Сначала проверить выбранные пути на изолированном тестовом проекте:

- Codex: установленный app-server, существующий штатный вход CLI, управление из Rust.
- Claude Code: установленный неизменённый CLI, его штатный вход и отдельный процесс с официальным Claude Agent SDK.
- Для каждого: обычный обмен сообщениями, потоковые события, запросы разрешений, остановка и продолжение сохранённой сессии.
- Наследование настроек, проектных инструкций, навыков и MCP; поведение привычных команд и вложений.
- Разделение состояний разных сессий и корректная обработка недоступного инструмента, неподходящей версии, отсутствующего входа и ограничения подписки.

Отдельно установить применимость условий встраивания Claude к выбранной схеме. Успешный технический запуск не заменяет эту проверку.

Результат этапа: зафиксированные совместимые версии и подтверждённое покрытие обязательных возможностей. Если обязательная возможность или подписочный сценарий не подтверждается, сначала пересмотреть способ подключения. Замена подписки API-ключом и молчаливое сокращение возможностей не соответствуют MVP.

Уточнение пользователя от 10 ноября 2026 года: локальный Claude Code недоступен, поэтому для первого этапа его подключение реализуется по флоу Orca и проверяется локально на границе SDK. Реальный подписочный запуск Claude здесь не требуется для продолжения разработки; его совместимость и применимость условий распространения остаются неподтверждёнными до отдельной проверки. Обязательные возможности готового приложения сохраняются. Текущие результаты приведены в [матрице совместимости](executor-compatibility.md).

## 2. Собрать основу локального приложения

- Tauri 2 и React с TypeScript для окна и рабочего интерфейса.
- Ядро на Rust для команд приложения, процессов и доступа к файлам.
- SQLite для проектов, пространств, сессий, истории, черновиков и расположения вкладок.
- Связь команд и событий с конкретными пространствами, сессиями и запусками.
- Разделение жизненного цикла окна и приложения.

Проверка: приложение открывается, сохраняет и восстанавливает состояние; ошибка команды показывается пользователю, а не превращается в успешный статус. Изменения схемы хранения сохраняют существующие данные.

## 3. Реализовать проекты, пространства и терминал

- Проекты и группы по принятой модели Orca.
- Git worktree для одного репозитория и пространства общей папки для нескольких вложенных проектов.
- Создание от выбранной исходной точки, отображение выполнения и ошибок.
- Явно настроенная команда подготовки; сохранение пространства при её ошибке.
- xterm.js в интерфейсе и portable-pty в Rust для системной оболочки.
- Архивирование и удаление с согласованными проверками; сохранение исходных файлов обычной папки.

Проверка: временные репозитории, несколько worktree, успешная и неуспешная подготовка, терминальный ввод и изменение размера. Ошибка удаления не теряет сведения о пространстве; незавершённая работа требует явного решения пользователя.

## 4. Встроить обычное общение с исполнителями

- Несколько сессий в пространстве с выбором Claude Code или Codex.
- Потоковый ответ, действия, запросы разрешений, остановка и продолжение.
- Наследование привычного окружения исполнителя и выбранных параметров запуска.
- Сохранение истории и черновиков; история доступна после удаления пространства.
- Видимое состояние выполняющихся, завершённых, ожидающих ввода и прерванных сессий.

Проверка: события и ответы на запросы разрешений попадают в правильную сессию; остановка действительно отражает состояние конкретного запуска. История одной сессии не подменяет внутреннее состояние другой.

Разрешены параллельные сессии в одном пространстве с отображением их активности. Их файлы общие, автоматическое согласование правок не входит в эту модель; независимые изменения выполняются в отдельных Git worktree.

## 5. Добавить редактор, просмотр изменений и Git

- CodeMirror 6: вкладки, подсветка, поиск, ручное редактирование.
- Автосохранение после 1,5 секунды без ввода и при уходе, немедленное сохранение по Cmd+S и отдельное хранение черновиков.
- Обнаружение внешнего изменения файла и сохранение обеих версий при конфликте.
- @codemirror/merge для отображения изменений.
- Подготовка файлов и отдельных фрагментов diff, коммиты и отправка через установленный Git.
- Список конфликтующих файлов, просмотр версий и ручное редактирование результата.

Проверка: внешнее изменение не уничтожает ручной черновик; выбранный фрагмент применяется к той версии, которую видел пользователь. Ошибки Git и его проверок отображаются, оставшиеся изменения сохраняются.

## 6. Завершить восстановление и подготовить готовое приложение

- Закрытие окна сохраняет работающие задачи.
- Cmd+Q предупреждает об активной работе и завершает процессы после подтверждения.
- После сбоя восстанавливаются сохранённые сообщения, черновики и вкладки; состояние прежних запусков сверяется перед продолжением.
- Команды после сбоя не повторяются автоматически.
- Среда Node.js и вспомогательный процесс Claude входят в готовое приложение.
- Claude Code и Codex остаются отдельно установленными инструментами пользователя.
- ADE обновляется вручную установкой новой версии с сохранением локальных данных.

Проверка: запуск готовой сборки, обнаружение CLI, работа без отдельно установленного для ADE Node.js, закрытие окна, полный выход, сбой и повторный запуск. Проверяется сохранение данных при обновлении приложения.

## Общий принцип реализации

Каждый этап заканчивается работающим сценарным результатом и соответствующими функциональными проверками. Для файловых операций, Git и восстановления используются временные данные и контролируемые сбои. Реальные подписочные проверки выполняются отдельно от таких локальных проверок.

Отдельные замеры производительности и нагрузочный прототип исключены по решению пользователя. Быстрый отклик и умеренное потребление памяти учитываются в устройстве приложения: история загружается порциями, очереди вывода ограничены, ресурсы закрытых представлений освобождаются, длительные операции не блокируют интерфейс.

## Что пока не подтверждено

- Работа подписочных интеграций с конкретными версиями и учётными записями.
- Применимость условий встраивания Claude SDK к выбранной схеме.
- Совместимость привычных возможностей CLI со встроенным чатом.
- Работоспособность готовой сборки и выполнение функциональных критериев MVP.

План не является отчётом о выполненной реализации или пройденных проверках.
