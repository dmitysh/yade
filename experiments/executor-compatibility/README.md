# Проверка совместимости исполнителей

Изолированные сценарии первого этапа. Приложение и его интерфейс здесь не создаются. Проверенные версии, результаты и препятствия записаны в [отчёте](../../docs/executor-compatibility.md).

Для реальных запусков нужна временная рабочая папка и штатный вход в установленный CLI. Сценарии создают обычные разговоры и используют лимиты подписки. Проверки SDK должны выполняться с неизменённым установленным Claude Code; путь к нему определяется через `PATH` и передаётся явно.

## Обнаружение и состояние входа

```sh
node experiments/executor-compatibility/check-cli.mjs
```

Сценарий проверяет установленные версии и текущее состояние входа, затем воспроизводит отсутствие программы и входа. Для отрицательных проверок используется отдельное временное состояние; выход из текущей учётной записи не выполняется. В вывод не включаются почта и учётные данные.

## Codex

Для команд нужны Rust и Cargo в `PATH`. Проверено с Rust `1.99.1` и Codex `0.167.0`. Сценарий выполняет установление соединения, проверку типа входа, создание или продолжение разговора и один запуск. События передаются в stdout в формате JSON по строкам; диагностика идёт в stderr. Завершение с ошибкой даёт ненулевой код выхода.

```sh
cargo test --locked --manifest-path experiments/executor-compatibility/codex/Cargo.toml
cargo clippy --locked --manifest-path experiments/executor-compatibility/codex/Cargo.toml --all-targets -- -D warnings
cargo run --locked --manifest-path experiments/executor-compatibility/codex/Cargo.toml -- /абсолютная/временная/папка 'Ответь точно YADE_STREAM_OK. Не используй инструменты.'
```

Для продолжения передайте последним аргументом `threadId` из первого запуска. История сообщений повторно не отправляется.

Матрица сравнивает app-server и обычный CLI на одних тестовых инструкциях, навыке, MCP, файле и изображении:

```sh
cargo build --locked --manifest-path experiments/executor-compatibility/codex/Cargo.toml
node experiments/executor-compatibility/codex/check-compatibility.mjs
```

Временная папка создаётся внутри текущего репозитория и удаляется после успеха. Для проверки обмена локальный MCP передаётся явными параметрами запуска. Отдельно `config/read` проверяет загрузку пользовательского слоя и фиксирует, загружен ли проектный слой или требуется сохранённое штатное доверие. Передача `projects.<путь>.trust_level` через `-c` не заменяет это доверие. Успешный обмен MCP с явными параметрами не доказывает загрузку проектного MCP. Сценарий не изменяет пользовательский файл настроек. При ошибке тестовые файлы и события остаются в созданной папке для диагностики.

## Claude Code

Сценарий использует SDK `0.2.141` и неизменённый установленный CLI; ранее проверена его инициализация с CLI `2.1.141`. Зависимости закреплены в `package-lock.json`. Для запуска TypeScript без отдельного преобразования нужен Node.js `22.18.0` или новее; локально использован `26.8.1`.

По решению пользователя локальный Claude не требуется восстанавливать. Проверки ниже выполняются без входа и сетевых запросов: подменяется только граница `query()`, проверяются параметры и управление SDK.

```sh
npm --prefix experiments/executor-compatibility/claude ci --omit=optional --ignore-scripts --no-audit --no-fund
npm --prefix experiments/executor-compatibility/claude run check
npm --prefix experiments/executor-compatibility/claude test
```

Реальный запуск остаётся отдельной проверкой на машине с работающим штатным входом Claude Code:

```sh
npm --prefix experiments/executor-compatibility/claude run probe -- /абсолютная/временная/папка 'Ответь точно YADE_CLAUDE_OK. Не используй инструменты.'
```

Для продолжения передайте последним аргументом исходный `session_id`. Сценарий передаёт только новое сообщение и штатный параметр `resume`. Инструкции и настройки загружаются из источников `user`, `project`, `local` с системными инструкциями `claude_code`; выбранный `CLAUDE_CONFIG_DIR` сохраняется. Это тот же способ загрузки, что в Orca. Каталог команд, навыков и состояние MCP из сообщений SDK передаются в вывод целиком. Реальное применение этих возможностей Claude остаётся непроверенным.

Как в Orca, изображения передаются перед объединённым текстовым блоком: Claude раскрывает команду из последнего текстового блока. Тест подтверждает, что команда со ссылкой на файл и изображением сохраняет этот порядок без дополнительных действий пользователя. Прерывание считается подтверждённым только после получения результата; отправка `interrupt()` сама по себе не означает остановку.

Проверка TypeScript остаётся строгой для собственного кода; проверка деклараций зависимостей отключена из-за отсутствующих типов в опубликованном `sdk.d.ts` версии `0.2.141`.

## Параметры проверочных сценариев

| Переменная | Назначение |
|---|---|
| `YADE_APPROVAL` | `decline` по умолчанию; `accept` разрешает запросы текущего запуска |
| `YADE_INTERRUPT_AFTER_MS` | Задержка до штатного прерывания в миллисекундах |
| `YADE_CODEX_BIN` | Путь Codex; используется также для проверки ошибки запуска |
| `YADE_CLAUDE_BIN` | Явный путь установленного Claude Code |
| `YADE_APPROVAL_POLICY` | Только Codex: проверка выбранной политики с `read-only` и обработкой разрешений пользователем |
| `YADE_INPUT_JSON` | Содержимое сообщения в штатном формате соответствующего подключения; уровень проверки вложений указан в матрице |

Оба сценария сохраняют только текущий поток в stdout; штатное состояние разговора остаётся у CLI. Сценарий Claude удаляет из окружения дочернего процесса переменные API-ключей и прямой передачи OAuth-токена. Учётные данные читает сам установленный CLI.
