# git-workflow Specification

## Purpose

Проверка и оформление изменений в конкретном репозитории: состояние, ветки, индексирование файлов и фрагментов, коммиты, отправка и ручное разрешение конфликтов.

## Requirements

### Requirement: Область Git-операции

Приложение ДОЛЖНО (SHALL) показывать текущую ветку либо коммит, состояние и изменения выбранного репозитория. В пространстве общей папки операция должна однозначно относиться к одному репозиторию.

#### Scenario: Выбор вложенного репозитория
- **WHEN** пользователь просматривает Git в пространстве с двумя репозиториями
- **THEN** показан выбранный репозиторий и его собственные ветка, индекс и изменения

#### Scenario: Обычная папка без Git
- **WHEN** пользователь открывает Git для папки без репозитория
- **THEN** отображается отсутствие репозитория, а команды Git не выполняются в постороннем расположении

### Requirement: Подготовка файлов

Приложение ДОЛЖНО (SHALL) позволять добавлять в индекс выбранные файлы целиком и просматривать подготовленные и неподготовленные изменения.

#### Scenario: Выбор одного файла
- **WHEN** пользователь добавляет в индекс один из нескольких изменённых файлов
- **THEN** в индекс попадают изменения выбранного файла
- **AND** остальные изменения не подготавливаются автоматически

### Requirement: Подготовка отдельных фрагментов

Приложение ДОЛЖНО (SHALL) позволять добавлять в индекс выбранные фрагменты diff только для версии, которую видел пользователь. При изменении сравниваемого содержимого требуется обновить diff и выбор до применения.

#### Scenario: Выбор одного фрагмента
- **WHEN** пользователь подготавливает один из нескольких фрагментов изменений файла
- **THEN** в индекс попадает только выбранный фрагмент
- **AND** остальные изменения файла остаются неподготовленными

#### Scenario: Устаревший diff
- **WHEN** рабочий файл или индекс изменился после выбора фрагмента
- **THEN** операция отклоняется с предложением обновить diff
- **AND** выбранный фрагмент не применяется к другой версии

#### Scenario: Ошибка применения фрагмента
- **WHEN** Git не может применить выбранный фрагмент
- **THEN** ошибка показана и отображается фактическое состояние индекса

### Requirement: Коммит и отправка

Приложение ДОЛЖНО (SHALL) позволять создать коммит подготовленных изменений и отправить изменения через установленный Git, показывая фактический результат и ошибки его штатных проверок и аутентификации.

#### Scenario: Успешный коммит
- **WHEN** пользователь создаёт коммит с сообщением из подготовленных изменений
- **THEN** создаётся коммит выбранного репозитория
- **AND** неподготовленные изменения в него не включаются

#### Scenario: Ошибка проверки коммита
- **WHEN** проверка или hook Git отклоняет коммит
- **THEN** показана причина и сохранены оставшиеся изменения
- **AND** не отображается успешный коммит

#### Scenario: Отказ отправки
- **WHEN** отправка отклоняется сервером, сетью или штатной аутентификацией Git
- **THEN** показана ошибка
- **AND** локальные коммиты и изменения сохраняются

### Requirement: Ручное разрешение конфликтов

Приложение ДОЛЖНО (SHALL) показывать конфликтующие файлы, доступные конфликтующие версии и позволять вручную редактировать результат и подготовить его через обычные операции Git.

#### Scenario: Конфликт слияния
- **WHEN** Git сообщает о конфликтующих файлах
- **THEN** они видны в списке, а их версии доступны для сравнения

#### Scenario: Подготовка результата
- **WHEN** пользователь вручную исправляет конфликтующий файл, сохраняет и добавляет его в индекс
- **THEN** Git получает сохранённое содержимое
- **AND** успешное разрешение показывается только по фактическому состоянию Git

### Requirement: Ошибки Git сохраняют работу

Приложение ДОЛЖНО (SHALL) отображать ошибки операций Git и обновлять состояние по фактическому результату без автоматического сброса файлов, индекса или истории.

#### Scenario: Неуспешная операция
- **WHEN** любая запрошенная операция Git завершается неуспешно
- **THEN** видны ошибка и оставшиеся изменения
- **AND** приложение не выполняет автоматический сброс или удаление работы
