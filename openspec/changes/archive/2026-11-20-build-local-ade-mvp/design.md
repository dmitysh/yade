# Design

## Context

Мотивация и границы заданы в [предложении](proposal.md). Проект новый: сейчас доступны [термины](../../../../CONTEXT.md), [MVP](../../../../docs/mvp.md), [архитектура](../../../../docs/architecture.md), [план](../../../../docs/implementation-plan.md) и четыре ADR; исходного кода, тестов и сборочной конфигурации нет.

Постановка, включая параллельные сессии с общими файлами, подтверждена пользователем. Обязательные исполнители — Claude Code и Codex с личными подписками и существующим штатным входом. Интерфейсы подключения сверены с Orca; это доказательство механизма, а не результатов запуска нашей сборки.

## Goals / Non-Goals

**Goals:**
- Разделить представление, локальные операции и управление внешними процессами так, чтобы закрытие окна не прерывало работу.
- Сохранить связь каждого события, разрешения и операции с конкретным пространством и запуском.
- Предотвращать потерю черновиков и применение устаревших фрагментов изменений.
- Ограничить загружаемую историю и очереди вывода без отдельных замеров производительности.
- Проверить обязательные интеграции до основной реализации интерфейса.

**Non-Goals:**
- Отдельная служба, продолжающая работу после полного выхода из ADE.
- Универсальная система подключаемых исполнителей, собственный цикл выполнения задач или единая конфигурация разных CLI.
- Полная копия устройства Orca: отдельный процесс SDK выбран для архитектуры Tauri/Rust.
- Новые численные обещания производительности; функциональные границы перечислены в предложении.

## Decisions

### 1. Tauri, Rust и React с TypeScript

Tauri 2 управляет окнами и системными событиями. React с TypeScript отображает рабочий интерфейс. Ядро Rust владеет файлами, Git, SQLite, PTY и процессами. Интерфейс вызывает предметные команды ядра и получает события.

Предлагаемая структура первого приложения: `src/` для интерфейса, `src-tauri/` для ядра и `claude-bridge/` для вспомогательного процесса SDK. Это будущие каталоги, сейчас их нет.

Выбор уже зафиксирован в [ADR 0002](../../../../docs/adr/0002-desktop-stack.md). Альтернатива — Electron с единой средой Node.js — упрощает размещение SDK, но меняет принятый стек и состав поставки. Нативные компоненты только macOS не выбираются: системные различия остаются на границах оболочки и запуска процессов.

### 2. Ядро живёт независимо от окна

Закрытие окна скрывает представление и сохраняет ядро с его процессами. Повторное открытие получает актуальное состояние из ядра и хранилища. Cmd+Q — отдельный путь: предупреждение при активной работе, отмена либо остановка принадлежащих ADE процессов и сохранение состояния.

Реестр запусков связывает процесс с пространством, сессией и запуском; учитываются дочерние процессы SDK, исполнителей, оболочек и команд подготовки. Для остановки используются сохранённые дескрипторы и подтверждаемая принадлежность процесса, а не только числовой PID. Сбой не считается доказательством завершения дочерних процессов.

Альтернатива — отдельный постоянно работающий демон — избыточна для выбранного поведения после полного выхода.

### 3. Два конкретных подключения исполнителей

**Codex:** Rust запускает установленный `codex app-server` и реализует необходимый обмен JSON-RPC через stdio: установление соединения, создание и продолжение разговора, выполнение, события, разрешения и прерывание. Сохраняется внешний идентификатор разговора; используется существующий штатный профиль CLI.

**Claude Code:** отдельный процесс TypeScript с официальным Claude Agent SDK запускает неизменённый установленный CLI. Node.js и этот процесс входят в сборку. Путь исполняемого файла, рабочая папка, штатная конфигурация, управление разрешениями и продолжением передаются явно в пределах поддерживаемого интерфейса SDK. Собственные токены приложение не извлекает.

Между Rust и вспомогательным процессом — локальный обмен сообщениями JSON по строкам stdio с корреляцией запросов и событий. Служебная диагностика отделяется от этого потока. Не вводятся сетевой сервер, дополнительный транспорт или система расширений.

Ядро проверяет адресацию ответа и актуальность запроса до отправки исполнителю. Представление показывает фактические состояния: готовность, выполнение, ожидание ввода, ожидание остановки, завершение, ошибку, прерывание или необходимость сверки прошлого запуска. Закрытие вкладки не является остановкой.

Достаточно двух конкретных обработчиков подключений и общего представления состояния. Универсальная иерархия исполнителей не требуется. Альтернатива — адресация по активной вкладке — допускает разрешение действия чужого запуска.

Альтернатива для Claude — собственный разбор управляющего протокола CLI — добавляет поддерживаемый протокол вместо использования официального SDK. Альтернатива для обоих — показывать только терминал — не обеспечивает принятый структурированный чат. Решение согласуется с [ADR 0001](../../../../docs/adr/0001-use-existing-executors.md) и [ADR 0004](../../../../docs/adr/0004-claude-sdk-process.md).

Проверенные исходники Orca и закреплённая ревизия приведены в [архитектуре](../../../../docs/architecture.md). Перед основной реализацией выполняется конкретная проверка совместимости, описанная ниже.

### 4. События и разрешения привязаны к запуску

У разговоров ADE есть собственные идентификаторы; внешний идентификатор разговора хранится отдельно. Каждый запуск имеет отдельный идентификатор. События содержат связь с пространством, сессией и запуском; запрос разрешения дополнительно имеет идентификатор исходного запроса исполнителя.

### 5. Модель пространств сохраняет границы репозиториев

Проекты и группы соответствуют [ADR 0003](../../../../docs/adr/0003-orca-workspace-model.md). Worktree относится к одному репозиторию; пространство папки — к существующей общей папке группы. Исходная ветка или коммит выбираются при создании. Команда подготовки запускается только если явно настроена; ошибка не удаляет созданное пространство.

Плюс на верхней панели, кнопка Git-проекта в каталоге и плюс у выбранного пространства открывают форму «Новое пространство» напрямую. Промежуточного окна управления нет; для обычной папки создание worktree недоступно. Размеры формы соответствуют окну нового чата и учитывают общие настройки шрифта и масштаба. В ней показаны проект, название пространства, исходная точка (`HEAD` по умолчанию) и обязательное имя новой ветки, которое по умолчанию повторяет название пространства до ручного изменения. Ядро автоматически размещает новые worktree в `~/yade/workspaces/<имя папки репозитория>/<название пространства>`, создаёт родительские папки и отклоняет названия `.` и `..`, а также названия с разделителями пути или нулевым символом. Конечная папка должна отсутствовать. Ветку и рабочую копию создаёт установленный Git; если имя ветки не передано ядру, используется название пространства. Пустое или недопустимое имя ветки отклоняется; создание с отсоединённым `HEAD` недоступно. Явно переданный ядру путь и пути существующих пространств сохраняются; новой настройки размещения нет. Архивирование, удаление, настройка и состояние подготовки сохраняются в ядре без отдельного интерфейса управления.

Сессии одного пространства разделяют файлы. Приложение показывает их активность; независимые изменения разделяются worktree. Группа не создаёт общей истории и атомарных коммитов нескольких репозиториев.

Архивирование сохраняет данные. Для удаления проверяются черновики, Git-состояние и несмерженные коммиты; удаление ветки требует отдельного подтверждения. Минимальное защитное правило: удалить пространство можно после остановки его выполняющихся сессий и терминальных процессов. При ошибке состояние сверяется с диском до изменения записи пространства.

Альтернатива — автоматически создавать отдельную копию для каждой сессии — меняет согласованный сценарий общих файлов.

### 6. SQLite хранит рабочий контекст, CLI — штатное состояние разговора

| Данные | Содержание и связь |
|---|---|
| Группы и проекты | Идентификаторы, названия, локальные пути и принадлежность группе |
| Пространства | Тип, связь с проектом или группой, путь, исходная точка, ветка либо коммит, архивирование и сведения об удалении |
| Сессии | Пространство, исполнитель, внешний идентификатор разговора и состояние |
| Запуски | Связь с сессией, состояние и сведения для проверки принадлежности и состояния процессов |
| Сообщения и события | Порядок и связь с разговором и запуском; доступны независимо от существования пространства |
| Черновики | Неотправленные сообщения, изменённый текст и исходная версия файла |
| Представление и настройки | Вкладки, панели, выбранный контекст и настройки ADE без хранилищ входа CLI |

Точная физическая схема определяется при создании хранилища в пределах этих связей. Изменения схемы выполняются транзакционно. История не удаляется каскадно вместе с пространством; отдельное удаление относится к выбранному разговору.

Сообщение сначала фиксируется в истории, затем публикуется как сохранённое. Ошибка записи видна пользователю. Для часто меняющегося представления и черновиков допускается объединение записей; при выходе ожидается завершение сохранения. Обещание восстановления относится к фактически сохранённым данным.

Альтернатива — считать копию видимых сообщений полной сессией исполнителя — не сохраняет его внутренний контекст и не используется для продолжения.

### 7. Редактор и Git используют проверяемые версии

CodeMirror 6 отвечает за базовое редактирование; `@codemirror/merge` — за сравнение. Дерево, вкладки, поиск по проекту и команды сохранения реализуются в ADE. Черновик и версия исходного содержимого сохраняются отдельно. Перед записью по Cmd+S версия на диске сверяется с исходной; расхождение показывает конфликт и сохраняет обе версии.

Git вызывается установленной программой с отдельными аргументами и явным рабочим каталогом. Для пространства общей папки репозиторий выбирается однозначно. Обычные пути и параметры не интерполируются в строку оболочки. Явно заданная пользователем команда подготовки выполняется как команда оболочки в своём пространстве.

Подготовка фрагмента использует diff конкретных версий индекса и рабочего файла. Перед применением их актуальность проверяется; устаревший выбор отклоняется. Само индексирование выполняется средствами Git. Изменяющие индекс операции ADE одного репозитория выполняются последовательно; внешнее изменение требует повторной проверки.

При конфликте доступны версии и ручной результат; отдельный сложный редактор слияний не создаётся. Альтернатива — собственная реализация Git либо применение фрагмента по совпавшей строке — усложняет поддержку и создаёт риск подготовки чужих изменений.

#### Типы файлов первого этапа

Решение от 12 ноября 2026 года: обязательный набор и границы поддержки зафиксированы в корневом [EDITOR_FILE_TYPES.md](../../../../EDITOR_FILE_TYPES.md), сценарии приёмки — в [спецификации редактора](specs/code-editor/spec.md). Это планируемая поддержка; новые задачи 9.6–9.11 остаются невыполненными до реализации и проверки. Выбран широкий набор повседневных языков, веб-форматов и конфигураций, для которых уже есть готовые режимы, без собственной реализации языковых анализаторов.

В текущем редакторе подключён `@codemirror/language-data` 6.5.2: каталог содержит 143 описания языков, а режим загружается по имени файла. Наличие описания не равно проверенной поддержке всего формата. Для первого этапа нужны явные соответствия специальных имён и недостающих вариантов: `.pyi`, `.zsh`, JSONC, файлов окружения и вариантов Dockerfile. JSONC нельзя свести к строгому JSON, а произвольный `.conf` — к Nginx. `go.mod`, Makefile и Terraform пока получают собственную иконку и текстовый режим. Языки вне обязательной матрицы могут работать через существующий каталог, но не считаются прошедшими приёмку.

При реализации сохраняем CodeMirror и ленивую загрузку имеющихся режимов, включая `StreamLanguage` для готовых режимов `@codemirror/legacy-modes`. Общие метаданные типа файла связывают имя, расширения, язык и иконку; ими пользуются дерево, вкладки, поиск, списки Git и сравнение. Особая иконка `package.json` или `Cargo.lock` не подменяет синтаксис содержимого. Язык определяется автоматически без отдельного переключателя в панели редактора. Сравнения получают контекст файла; вложенные языки HTML, Vue и Markdown используют возможности соответствующих пакетов.

Для иконок выбираем ограниченный набор локальных SVG из Material Icon Theme с сохранением уведомления MIT. Не подключаем расширение VS Code, механизм тем иконок или сетевую загрузку ресурсов. Берём только изображения для заявленных типов и категорий; неизвестному типу остаётся общая иконка. Различия языка и назначения файла задаются явно, а не цепочками независимых условий в каждом компоненте.

Поддержка первого этапа включает подсветку и общий набор редактора: номера строк, поиск и замену, историю отмены, работу со скобками и отступами средствами выбранного режима, черновики и безопасное сохранение. Сворачивание и другие возможности конкретного режима не обещаются одинаковыми для всех языков. Для Go и TypeScript/JavaScript добавлены семантическое автодополнение, переходы по символам, подсказки типов, диагностика, поиск символов и переименование через `@codemirror/lsp-client`, `gopls` и `typescript-language-server`; управление и границы описаны в [навигации по коду](../../../../docs/code-navigation.md). Отладчик и автоматическое форматирование отложены. Svelte, Astro, GraphQL и HCL не входят в обязательный набор подсветки; их текст в UTF-8 можно редактировать. Файл Jupyter можно открыть как обычный текст и вручную выбрать JSON, без выполнения ячеек. Встроенный просмотр Markdown, изображений и PDF, табличный редактор CSV и перекодирование также отложены; SVG редактируется как XML без выполнения содержимого.

Проверка при реализации: соответствие имён и расширений всей матрице, реальные токены подсветки каждого режима, комментарии JSONC, вложенные языки, одинаковые иконки во всех местах, автоматическое определение языка без отдельного переключателя, сравнения и работа без сети. Отдельно проверяются LF, CRLF, BOM и отказ редактирования двоичных данных и неподдерживаемых кодировок. Существующие автосохранение и защита черновиков продолжают действовать для всех текстовых режимов.

Источники: [описания языков и определение по имени в CodeMirror](https://codemirror.net/docs/ref/#language.LanguageDescription), [каталог языков](https://github.com/codemirror/language-data), [потоковые режимы](https://github.com/codemirror/legacy-modes), [Material Icon Theme](https://github.com/material-extensions/vscode-material-icon-theme), [лицензия набора](https://github.com/material-extensions/vscode-material-icon-theme/blob/main/LICENSE). При исследовании проверены установленный каталог и загрузчики обычных форматов; это не проверка будущего интерфейса и всей матрицы подсветки.

### 8. Терминал и длительные операции не блокируют представление

xterm.js с `@xterm/addon-fit` отображает терминал, portable-pty в Rust управляет оболочкой, вводом, размером и завершением. Чтение PTY и ожидание процессов выполняются вне потока интерфейса.

Очереди вывода ограничены; при отставании потребителя применяется регулирование чтения, а не бесконечное накопление. Объём прокрутки терминала ограничивается. История разговоров читается порциями, отображается видимая часть; закрытые представления освобождают ресурсы без остановки выполняющихся задач. Файловые и Git-операции публикуют состояние и результат.

Альтернатива — загружать все разговоры и весь вывод при старте — противоречит качественным требованиям к памяти. Численные нормативы и отдельные замеры не вводятся.

### 9. Проверка интеграций предшествует основному интерфейсу

На изолированном проекте проверить для обоих исполнителей подписочный вход, сообщения, поток, действия, разрешения, прерывание и продолжение. Проверить пользовательские и проектные настройки, инструкции, навыки, MCP, привычные команды и вложения. Зафиксировать рабочие версии CLI и SDK и результат каждого сценария.

Применимость условий встраивания Claude устанавливается отдельно от успешного запуска. Если обязательный сценарий не подтверждён, реализация зависимого интерфейса останавливается до пересмотра подключения и обновления плановых артефактов. Переход на API-ключи или молчаливое исключение обязательной возможности не являются допустимым обходом.

Уточнение пользователя от 10 ноября 2026 года: локальный Claude Code недоступен; выбранный флоу реализуется аналогично Orca без требования восстановить вход на этой машине. Для Claude в первом этапе достаточно сверки исходников Orca и локальных тестов параметров и управления SDK. Недоступный реальный запуск не блокирует дальнейшую реализацию. Это исключение относится к способу проверки первого этапа: сообщения, поток, разрешения, прерывание, продолжение и наследование конфигурации остаются обязательными для готового приложения. Реальная совместимость и применимость условий распространения записываются отдельно как неподтверждённые.

Это конкретный первый этап уже принятого плана, а не отложенный выбор архитектуры или обещание совместимости.

## Risks / Trade-offs

- [CLI или SDK меняет протокол либо подписочный сценарий недоступен] → Проверить обязательные сценарии первым этапом, зафиксировать совместимые версии и показывать несовместимость при обнаружении.
- [Условия встраивания Claude не применимы к выбранной упаковке] → Установить применимость до основной реализации; при отрицательном результате пересмотреть подключение без подмены штатного входа.
- [Параллельные сессии меняют один файл] → Показывать активность и общность файлов, сохранять черновики; независимую работу выполнять в разных worktree.
- [Внешняя программа меняет файл или индекс во время операции ADE] → Проверять исходные версии и отклонять устаревшие действия; приложение не обещает глобальную координацию сторонних процессов.
- [Процесс переживает сбой или PID используется повторно] → Проверять принадлежность и состояние прежнего запуска, не повторять команды автоматически и не завершать процесс только по совпавшему PID.
- [Отдельный Node.js увеличивает поставку и число процессов] → Включать одну согласованную среду для вспомогательного процесса и не запускать сохранённые сессии без необходимости.
- [Различия системного WebView и механизмов процессов на других ОС] → Сохранять платформенные границы в оболочке; первый выпуск проверять только на macOS.
- [Без замеров нельзя подтвердить численные показатели скорости и памяти] → Применять ограничение очередей, порционную историю и освобождение ресурсов; приёмка остаётся функциональной.
- [Сбой при обновлении структуры данных] → Транзакционные миграции и сохранение исходной базы для восстановления; обновление не должно перезаписывать её частично.

## Migration Plan

1. Выпустить первое приложение после прохождения сценариев всех девяти спецификаций. До этого нет развёрнутой версии и пользовательской базы для переноса.
2. Собирать интерфейс, Rust-ядро, Node.js и процесс Claude как одну готовую поставку macOS. CLI и Git обнаруживать на компьютере пользователя.
3. Хранить изменяемые данные отдельно от устанавливаемого приложения; фиксировать версию схемы и сохранять исходные данные до её обновления.
4. Проверять ручную установку следующей версии с сохранёнными проектами, историями и черновиками, а также отказ миграции.
5. При неуспешной миграции сохранить исходное состояние. Возврат старой версии допускается с её совместимой базой; чтение ею более новой схемы не предполагается.
