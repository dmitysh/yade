# Редактор кода

## Purpose

Просмотр и ручное изменение исходников в рабочем пространстве с поиском, сравнением версий и сохранением несохранённых правок при внешних изменениях.

## ADDED Requirements

### Requirement: Навигация и помощь при редактировании Go и TypeScript

Приложение ДОЛЖНО (SHALL) предоставлять для Go и TypeScript/JavaScript, включая TSX/JSX, переходы к определению, типу и реализации, поиск использований и символов, структуру файла, автодополнение, подсказки типов, переименование и диагностику через готовые языковые серверы. Оформление ДОЛЖНО (SHALL) использовать существующие компоненты и стили Yade, управление — сочетания JetBrains для macOS.

#### Scenario: Поиск и возврат к исходному месту
- **WHEN** пользователь вызывает двойной Shift и выбирает файл или символ
- **THEN** приложение открывает обычную вкладку в нужной позиции
- **AND** пользователь может вернуться назад и вперёд с восстановлением позиции курсора
- **AND** поиск файлов и текста учитывает `.gitignore`; поиск текста поддерживает регистр, целое слово, регулярное выражение и маски файлов

#### Scenario: Недостающая поддержка языка
- **WHEN** нужный языковой сервер не найден
- **THEN** приложение предлагает установку по кнопке в собственный каталог данных
- **AND** не устанавливает автоматически Go или Node.js
- **AND** редактирование текста остаётся доступным при отсутствии сервера или ошибке подключения

#### Scenario: TypeScript в пространстве без подтверждения доверия
- **WHEN** открыт файл TypeScript или JavaScript в пространстве без подтверждения доверия
- **THEN** редактор сохраняет подсветку и редактирование текста
- **AND** языковой сервер запускается только после явного подтверждения доверия к пространству

#### Scenario: Переход во внешнюю зависимость
- **WHEN** языковой сервер возвращает определение в стандартной библиотеке или внешней зависимости
- **THEN** приложение открывает этот файл только для чтения
- **AND** не разрешает произвольное чтение внешних путей и доступ к `.git`

#### Scenario: Предварительный просмотр переименования
- **WHEN** пользователь вводит новое имя символа
- **THEN** приложение показывает затронутые файлы и сравнение с текущим текстом, включая несохранённые правки
- **AND** приостанавливает автосохранение на время диалога
- **AND** применяет изменения только после подтверждения и повторной проверки версий файлов и черновиков
- **AND** при конфликте не затирает внешние или ручные правки

#### Scenario: Сообщения языкового сервера
- **WHEN** сервер присылает диагностику
- **THEN** приложение показывает ошибки и предупреждения в редакторе и общем списке с переходами
- **AND** не выдаёт этот список за полную проверку проекта сборкой или линтером

### Requirement: Файлы и вкладки

Приложение ДОЛЖНО (SHALL) предоставлять дерево файлов пространства, открытие нескольких текстовых файлов во вкладках, подсветку синтаксиса и ручное редактирование.

#### Scenario: Открытие файлов
- **WHEN** пользователь открывает два текстовых файла из дерева
- **THEN** каждый доступен в своей вкладке с содержимым выбранного пространства

#### Scenario: Изменение текста
- **WHEN** пользователь редактирует файл
- **THEN** изменённое содержимое видно в редакторе и отмечено как несохранённое

### Requirement: Поддерживаемые текстовые форматы

Приложение ДОЛЖНО (SHALL) поддерживать обязательный набор текстовых форматов первого этапа из [EDITOR_FILE_TYPES.md](../../../../../../EDITOR_FILE_TYPES.md). Для каждого формата доступны подсветка синтаксиса, автоматическое определение языка и отдельная узнаваемая иконка типа. Поддержка относится к тексту в UTF-8 и не означает наличие проверки типов или других семантических возможностей IDE.

#### Scenario: Открытие формата из обязательного набора
- **WHEN** пользователь открывает файл из основной матрицы [EDITOR_FILE_TYPES.md](../../../../../../EDITOR_FILE_TYPES.md#основная-матрица)
- **THEN** редактор автоматически выбирает соответствующий режим подсветки
- **AND** файл получает иконку своего типа; варианты одного типа используют общую иконку

#### Scenario: JSON с комментариями
- **WHEN** открыт файл JSONC, в том числе `tsconfig.json`, с комментариями и завершающими запятыми
- **THEN** комментарии и значения получают соответствующую подсветку
- **AND** допустимые для JSONC конструкции не показываются как синтаксическая ошибка строгого JSON

#### Scenario: Вложенные языки
- **WHEN** открыт HTML со стилями и скриптом, Vue с блоками `template`, `script`, `style` либо Markdown с именованным блоком кода
- **THEN** вложенные HTML, JavaScript, TypeScript, CSS и языки блоков Markdown из обязательного набора получают соответствующую подсветку
- **AND** неизвестный язык блока Markdown отображается как обычный текст внутри блока

### Requirement: Автоматическое определение языка

Приложение ДОЛЖНО (SHALL) определять язык по специальному имени файла и затем по наиболее точному известному расширению. Если соответствия нет, учитывается известный интерпретатор в первой строке `#!`. Отдельного переключателя языка в панели редактора нет.

#### Scenario: Специальное имя важнее расширения
- **WHEN** пользователь открывает `CMakeLists.txt`, `Cargo.lock`, `.env.local` или `Dockerfile.dev`
- **THEN** выбирается соответственно CMake, TOML, режим переменных окружения или Dockerfile
- **AND** общий суффикс не заменяет это соответствие

#### Scenario: Неоднозначное расширение
- **WHEN** пользователь открывает `.h` или неизвестный `.conf`
- **THEN** `.h` по умолчанию открывается как C, а неизвестный `.conf` — как обычный текст

#### Scenario: Скрипт без известного расширения
- **WHEN** первая строка файла без соответствия имени или расширению задаёт `sh`, `bash`, `zsh`, `python`, `python3` или `node` через прямой путь либо `/usr/bin/env <интерпретатор>`
- **THEN** выбирается соответственно режим оболочки, Python или JavaScript
- **AND** содержимое файла не выполняется

#### Scenario: Подсветка без ручного выбора
- **WHEN** пользователь открывает текстовый файл
- **THEN** режим подсветки определяется автоматически без переключателя в панели редактора
- **AND** загрузка подсветки не меняет текст, курсор, историю отмены и черновик

### Requirement: Единые иконки файлов

Приложение ДОЛЖНО (SHALL) показывать одинаковую иконку типа для одного файла в дереве, файловой вкладке, результатах поиска и списках Git. Особые имена могут получать собственную иконку без изменения языка содержимого. Различимость типов не должна зависеть только от цвета; имя и путь файла остаются доступны текстом.

#### Scenario: Узнаваемые типы
- **WHEN** рядом отображаются файлы Go, Rust, JavaScript, TypeScript, JSX, TSX, JSON и YAML
- **THEN** каждый тип узнаваем по символу или обозначению, включая различие JSX и TSX
- **AND** иконки читаемы во всех доступных темах и при поддерживаемом масштабе интерфейса

#### Scenario: Особые файлы проекта
- **WHEN** отображается файл из раздела [«Специальные файлы и иконки»](../../../../../../EDITOR_FILE_TYPES.md#специальные-файлы-и-иконки)
- **THEN** используется иконка указанного назначения, а режим содержимого определяется отдельно

#### Scenario: Иконка без встроенного просмотра
- **WHEN** в дереве или списках Git отображается изображение, PDF, архив, шрифт, исполняемый файл или двоичная база данных
- **THEN** файл получает иконку соответствующей категории
- **AND** иконка не означает наличие встроенного просмотра или редактирования этого формата

### Requirement: Безопасный текстовый режим

Приложение ДОЛЖНО (SHALL) позволять редактировать нераспознанные текстовые файлы в UTF-8 в режиме «Обычный текст» с общей иконкой. Двоичные файлы и неподдерживаемые кодировки не должны превращаться в редактируемый текст с заменой байтов. Открытие и определение языка не записывают файл и не запускают его содержимое.

#### Scenario: Неизвестный текстовый формат
- **WHEN** пользователь открывает текстовый файл, для которого не найдено соответствие по имени, расширению или строке `#!`
- **THEN** доступны обычное редактирование, поиск, отмена, черновик и существующее безопасное сохранение
- **AND** отсутствие подсветки не препятствует работе с текстом

#### Scenario: Неподдерживаемое содержимое
- **WHEN** пользователь пытается открыть двоичный файл, PDF, растровое изображение для просмотра либо текст в UTF-16 или Windows-1251
- **THEN** показано понятное сообщение о неподдерживаемом формате или кодировке
- **AND** файл не открывается для текстового редактирования, не перекодируется и не перезаписывается
- **AND** SVG открывается только как исходный XML без выполнения встроенного содержимого

#### Scenario: Окончания строк и кодировка
- **WHEN** пользователь открывает и сохраняет файл в UTF-8 с LF либо CRLF и необязательным BOM
- **THEN** автоматическое определение языка само по себе не меняет содержимое
- **AND** сохранение ручных правок сохраняет исходный вид окончаний строк и наличие BOM

### Requirement: Подсветка при сравнении версий

Приложение ДОЛЖНО (SHALL) использовать режим языка выбранного файла при сравнении его текстовых версий, включая сравнение с диском и сравнения Git. Подсветка синтаксиса и обозначение добавленных и удалённых строк должны оставаться различимыми и не влиять на содержимое версий.

#### Scenario: Сравнение поддерживаемого формата
- **WHEN** пользователь открывает сравнение версий TypeScript, Go, JSONC или другого формата из обязательного набора
- **THEN** обе стороны используют соответствующую подсветку синтаксиса вместе с обозначением различий
- **AND** для неизвестного формата сохраняется обычное текстовое сравнение

### Requirement: Поиск по коду

Приложение ДОЛЖНО (SHALL) предоставлять текстовый поиск по открытому документу и файлам выбранного проекта или пространства с переходом к найденному месту.

#### Scenario: Поиск в документе
- **WHEN** пользователь ищет текст в открытом файле
- **THEN** видны совпадения и доступен переход между ними

#### Scenario: Поиск в пространстве
- **WHEN** пользователь ищет текст по исходникам выбранного пространства
- **THEN** результаты указывают соответствующие файлы и места
- **AND** переход открывает найденное место в правильной рабочей копии

### Requirement: Автоматическое сохранение исходного файла

Приложение ДОЛЖНО (SHALL) автоматически записывать ручные правки в исходный файл после 1,5 секунды без ввода, при переключении или закрытии файловой вкладки, переключении пространства и уходе из приложения. Автосохранение всегда включено; обычные клики по панелям не ускоряют запись. Cmd+S сохраняет немедленно. Отдельная резервная запись черновика не должна сама по себе изменять исходный файл.

#### Scenario: Сохранение после паузы
- **WHEN** пользователь не меняет текст 1,5 секунды и внешнего конфликта нет
- **THEN** текущий текст записывается в исходный файл
- **AND** отметка несохранённых правок на вкладке снимается после успешной записи

#### Scenario: Сохранение при уходе
- **WHEN** пользователь переключает вкладку или пространство, закрывает файл либо приложение теряет фокус или скрывается
- **THEN** ожидающее сохранение запускается немедленно

#### Scenario: Ввод во время записи
- **WHEN** пользователь продолжает редактирование во время сохранения
- **THEN** ввод остаётся доступным и новые правки не заменяются ответом предыдущей записи
- **AND** следующая запись сохраняет новые правки относительно последней успешно записанной версии

#### Scenario: Сохранение по команде
- **WHEN** пользователь нажимает Cmd+S для изменённого файла, а внешнего конфликта нет
- **THEN** текущее содержимое записывается в этот файл и признак несохранённых правок снимается

#### Scenario: Резервный черновик до автосохранения
- **WHEN** пользователь меняет текст, а срок автосохранения ещё не наступил
- **THEN** текст и его исходная версия сохраняются отдельно для восстановления
- **AND** файл на диске пока остаётся прежним

#### Scenario: Ошибка записи
- **WHEN** сохранить исходный файл не удалось
- **THEN** показана ошибка
- **AND** черновик и признак несохранённых правок сохраняются
- **AND** вкладка показывает заметный значок с пояснением ошибки

#### Scenario: Закрытие после ошибки записи
- **WHEN** исходный файл записать не удалось, но резервный черновик сохранён
- **THEN** вкладку и приложение можно закрыть без потери черновика
- **AND** если не удалось сохранить и черновик, закрытие блокируется с понятной ошибкой

#### Scenario: Компактный интерфейс сохранения
- **WHEN** открыт файл
- **THEN** полный путь доступен в подсказке вкладки, а несохранённые правки отмечены точкой
- **AND** отдельный блок с путём, постоянным статусом и кнопками сохранения отсутствует

### Requirement: Защита черновика при внешнем изменении

Приложение ДОЛЖНО (SHALL) сохранять несохранённый черновик отдельно с исходной версией файла. Если содержимое на диске изменилось, оно не должно автоматически заменять черновик, а сохранение не должно молча перезаписывать внешние изменения.

#### Scenario: Внешняя правка при наличии черновика
- **WHEN** исполнитель или другая программа меняет файл с несохранёнными ручными правками
- **THEN** редактор показывает конфликт
- **AND** ручная и внешняя версии доступны до решения пользователя
- **AND** автосохранение приостановлено до ручного разрешения конфликта

#### Scenario: Внешняя правка без ручных изменений
- **WHEN** другая программа меняет файл без несохранённых ручных правок
- **THEN** редактор автоматически принимает новую версию без конфликта и записи файла

#### Scenario: Перезапуск с черновиком
- **WHEN** приложение запускается после завершения или сбоя с сохранённым черновиком
- **THEN** черновик восстанавливается отдельно от актуального файла
- **AND** при совпадении файла с исходной версией черновика автосохранение возобновляется
- **AND** при расхождении сохраняются обе версии и показывается конфликт

#### Scenario: Внешнее удаление файла
- **WHEN** открытый файл с черновиком удалён снаружи
- **THEN** черновик остаётся доступным, а отсутствие файла отображается как конфликт

### Requirement: Просмотр изменений

Приложение ДОЛЖНО (SHALL) показывать сравнение выбранных версий текста и подготовленных и неподготовленных изменений репозитория, не изменяя файлы при самом просмотре.

#### Scenario: Открытие сравнения
- **WHEN** пользователь открывает изменения файла
- **THEN** показаны соответствующие версии и различия
- **AND** само открытие сравнения не меняет файл или индекс Git
