# Состояние и жизненный цикл

## Purpose

Сохранение локального рабочего контекста и управление выполнением при закрытии окна, полном выходе и сбоях без потери сохранённой работы и повторного запуска команд.

## ADDED Requirements

### Requirement: Сохранение рабочего контекста

Приложение ДОЛЖНО (SHALL) локально сохранять проекты, группы, пространства, связи сессий, сообщения, неотправленные сообщения, файловые черновики, настройки и расположение вкладок и панелей. Ошибка сохранения должна быть видна пользователю.

#### Scenario: Повторный запуск
- **WHEN** приложение запускается с ранее сохранённым состоянием
- **THEN** восстанавливается рабочий контекст с соответствующими проектами, сессиями, черновиками и расположением представлений

#### Scenario: Ошибка локального сохранения
- **WHEN** запись состояния завершается ошибкой
- **THEN** пользователь видит, что состояние не сохранено
- **AND** интерфейс не сообщает об успешном сохранении

### Requirement: Независимое хранение истории

Приложение ДОЛЖНО (SHALL) сохранять историю разговоров после архивирования или удаления пространства до отдельного явного удаления истории пользователем.

#### Scenario: Чтение после удаления пространства
- **WHEN** пространство удалено, но пользователь не удалял разговор
- **THEN** история остаётся доступна для чтения с указанием отсутствующего пространства

#### Scenario: Явное удаление истории
- **WHEN** пользователь явно удаляет выбранную историю
- **THEN** удаляется выбранная история
- **AND** истории остальных сессий сохраняются

### Requirement: Закрытие и повторное открытие окна

Приложение ДОЛЖНО (SHALL) сохранять выполнение сессий и терминальных процессов при закрытии окна. Повторное открытие окна должно показывать их актуальное состояние.

#### Scenario: Закрытие при активной работе
- **WHEN** пользователь закрывает окно с выполняющейся сессией и терминальной командой
- **THEN** процессы продолжают работу

#### Scenario: Возврат к работающему приложению
- **WHEN** пользователь вновь открывает окно продолжающего работать приложения
- **THEN** видны поступившие сообщения и актуальные состояния
- **AND** те же задачи не запускаются повторно

### Requirement: Полный выход

При Cmd+Q с активной работой приложение ДОЛЖНО (SHALL) предупредить пользователя и позволить отменить выход. После подтверждения оно должно завершить принадлежащие ему процессы, включая дочерние процессы, и сохранить состояние.

#### Scenario: Отмена выхода
- **WHEN** пользователь отменяет предупреждение о полном выходе
- **THEN** приложение остаётся работать, а активные задачи продолжаются

#### Scenario: Подтверждение выхода
- **WHEN** пользователь подтверждает полный выход при активных сессиях и терминалах
- **THEN** принадлежащие приложению процессы завершаются и состояние сохраняется
- **AND** посторонние процессы пользователя не завершаются

### Requirement: Восстановление после сбоя

После сбоя приложение ДОЛЖНО (SHALL) восстановить сохранённые данные и обозначить незавершённые сессии как прерванные либо требующие сверки прежнего запуска. До продолжения проверяется состояние прежних процессов; команды не повторяются автоматически.

#### Scenario: Сбой во время выполнения
- **WHEN** приложение запускается после сбоя с незавершённой сессией
- **THEN** сохранённые сообщения и черновики восстановлены
- **AND** команды не повторяются, продолжение требует действия пользователя

#### Scenario: Прежний процесс сохранился
- **WHEN** при восстановлении обнаружена продолжающая работать задача прошлого запуска
- **THEN** её состояние показывается или отмечается как требующее проверки
- **AND** дублирующий запуск не создаётся автоматически

### Requirement: Отзывчивость и ограниченные ресурсы

Приложение ДОЛЖНО (SHALL) сохранять доступность интерфейса при длительных файловых, Git- и терминальных операциях, ограничивать накопление вывода и загружаемой истории и освобождать ресурсы закрытых представлений.

#### Scenario: Длительная работа
- **WHEN** терминал выдаёт продолжительный поток вывода либо выполняется долгая операция
- **THEN** пользователь может переключать представления и управлять текущей работой
- **AND** вывод не накапливается в неограниченной очереди

#### Scenario: Большая сохранённая история
- **WHEN** пользователь открывает сессию с большой историей
- **THEN** история подгружается частями
- **AND** остальные сохранённые сессии не запускаются ради отображения списка
