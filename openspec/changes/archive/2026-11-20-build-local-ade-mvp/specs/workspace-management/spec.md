# Рабочие пространства

## Purpose

Управление рабочими копиями репозиториев и общими папками, включая подготовку, архивирование и удаление с сохранением незавершённой работы.

## ADDED Requirements

### Requirement: Рабочее пространство репозитория

Приложение ДОЛЖНО (SHALL) создавать Git worktree одного выбранного репозитория от выбранной исходной ветки или коммита и показывать его путь, ветку либо коммит и результат создания. При создании всегда создаётся новая ветка. По умолчанию её имя совпадает с названием пространства; пользователь может изменить его вручную. Если имя ветки не передано ядру, используется название пространства. Создание с отсоединённым `HEAD` недоступно.

#### Scenario: Создание с новой веткой
- **WHEN** пользователь указал имя новой ветки и существующую исходную ветку или коммит
- **THEN** Git создаёт новую ветку от выбранной исходной точки и отдельную рабочую копию на этой ветке

#### Scenario: Имя ветки по названию пространства
- **WHEN** пользователь вводит или меняет название пространства, не редактируя имя ветки вручную
- **THEN** поле новой ветки повторяет название пространства
- **AND** вручную заданное имя ветки сохраняется при последующих изменениях названия

#### Scenario: Пустое имя новой ветки
- **WHEN** пользователь очистил поле новой ветки или ввёл только пробелы
- **THEN** создание недоступно до ввода имени ветки

#### Scenario: Независимая рабочая копия
- **WHEN** пользователь создаёт два пространства репозитория от выбранных исходных точек
- **THEN** получаются отдельные рабочие копии
- **AND** изменение файлов одной копии не изменяет файлы другой

#### Scenario: Ошибка создания
- **WHEN** Git не смог создать worktree
- **THEN** показывается ошибка и фактическое состояние операции
- **AND** не отображается успешно созданное пространство, которого нет
- **AND** форма остаётся открытой с введёнными значениями для исправления и повторной попытки

### Requirement: Форма создания пространства

Приложение ДОЛЖНО (SHALL) открывать отдельное окно «Новое пространство» напрямую кнопкой с плюсом на верхней панели, одноимённой кнопкой Git-проекта в каталоге и плюсом у выбранного пространства. Промежуточного окна управления пространствами нет. Окно ДОЛЖНО (SHALL) показывать название проекта, обязательные поля «Название пространства», «Исходная ветка или коммит» и «Новая ветка», подсказку о создании новой ветки от исходной точки и кнопки «Отмена» и «Создать пространство». Поле ручного ввода пути отсутствует. Размеры шрифтов и полей ДОЛЖНЫ (SHALL) соответствовать окну нового чата и учитывать общие настройки шрифта и масштаба.

#### Scenario: Прямое открытие создания
- **WHEN** пользователь нажимает кнопку создания на верхней панели или в каталоге Git-проекта
- **THEN** сразу открывается форма выбранного проекта без промежуточного окна архивирования, удаления или настройки подготовки

#### Scenario: Проект без Git
- **WHEN** выбран проект обычной папки или пространство общей папки
- **THEN** создание Git worktree недоступно

#### Scenario: Общий масштаб интерфейса
- **WHEN** пользователь меняет общий масштаб интерфейса
- **THEN** форма масштабируется вместе с окном нового чата, сохраняя одинаковые размеры шрифтов и полей при одинаковых настройках
- **AND** ширина формы ограничена размером окна

#### Scenario: Начальное состояние формы
- **WHEN** пользователь открывает форму создания пространства
- **THEN** фокус находится в пустом поле названия, исходная точка равна `HEAD`, новая ветка не задана
- **AND** кнопка создания недоступна, пока название, исходная точка или имя новой ветки пусты либо состоят только из пробелов

#### Scenario: Выполнение создания
- **WHEN** пользователь заполнил обязательные поля и нажал «Создать пространство»
- **THEN** поля и кнопки блокируются, показано «Создание пространства…»
- **AND** после успешного создания окно закрывается и список пространств обновляется

#### Scenario: Отмена до создания
- **WHEN** пользователь нажимает «Отмена», крестик или Escape до отправки формы
- **THEN** окно закрывается без создания worktree или ветки

### Requirement: Выбор исходной ветки

Приложение ДОЛЖНО (SHALL) загружать локальные и известные удалённые ветки выбранного Git-проекта и предоставлять их выбор через список с поиском рядом с полем исходной точки. Список ДОЛЖЕН (SHALL) содержать `HEAD` и ветки, исключая теги и символические ссылки, без автоматического сетевого обновления. Ручной ввод ветки, `HEAD` или хеша коммита ДОЛЖЕН (SHALL) оставаться доступным.

#### Scenario: Поиск и выбор ветки
- **WHEN** пользователь открывает список, вводит часть имени и выбирает ветку
- **THEN** список фильтруется без учёта регистра, а выбранная ветка подставляется в исходную точку
- **AND** создание worktree использует выбранную исходную точку

#### Scenario: Закрытие списка
- **WHEN** пользователь нажимает Escape в открытом списке
- **THEN** закрывается только список, а форма и введённые значения сохраняются

#### Scenario: Ошибка загрузки веток
- **WHEN** ядро не смогло прочитать ветки выбранного проекта
- **THEN** показана причина ошибки, а ветку или коммит можно ввести вручную и использовать при создании

### Requirement: Автоматическое расположение worktree

При отсутствии явно переданного пути ядро ДОЛЖНО (SHALL) размещать новый worktree в `~/yade/workspaces/<имя папки репозитория>/<название пространства>` с автоматическим созданием родительских папок. Пробелы по краям названия убираются. Конечная папка не должна существовать; ядро ДОЛЖНО (SHALL) отклонять названия `.`, `..`, названия с `/`, `\` или нулевым символом. Ранее сохранённые пути пространств не меняются.

#### Scenario: Путь выбран автоматически
- **WHEN** форма передаёт название пространства без пути
- **THEN** ядро определяет путь по имени папки выбранного репозитория и названию пространства и передаёт его Git
- **AND** отсутствующие родительские папки создаются автоматически

#### Scenario: Недопустимое название
- **WHEN** название содержит разделитель пути, нулевой символ либо после удаления пробелов по краям равно `.` или `..`
- **THEN** создание отклоняется без выхода за пределы папки пространств проекта

#### Scenario: Конечная папка уже существует
- **WHEN** по вычисленному пути уже есть папка
- **THEN** создание отклоняется с причиной ошибки, а существующие файлы сохраняются

#### Scenario: Расположение уже зарегистрировано
- **WHEN** вычисленный путь уже закреплён за неудалённым worktree, в том числе после неудачного создания
- **THEN** показывается понятное сообщение о занятом расположении с предложением указать другое название пространства вместо технической ошибки ограничения SQLite
- **AND** существующее пространство, его история и сведения о предыдущей ошибке сохраняются

### Requirement: Рабочее пространство общей папки

Приложение ДОЛЖНО (SHALL) открывать существующую общую папку группы как рабочее пространство с несколькими вложенными проектами, сохраняя отдельную область Git для каждого репозитория.

#### Scenario: Несколько вложенных репозиториев
- **WHEN** открыта общая папка группы с двумя репозиториями
- **THEN** сессия может работать в общей папке
- **AND** интерфейс не представляет репозитории как одну общую ветку или атомарный коммит

### Requirement: Подготовка нового worktree

Ядро ДОЛЖНО (SHALL) запускать явно настроенную для проекта команду подготовки после создания нового Git worktree, сохранять её вывод и итог и сохранять пространство при ошибке. Команда настройки и состояние подготовки доступны в ядре; элементов настройки и показа вывода в текущем интерфейсе нет.

#### Scenario: Настроенная подготовка
- **WHEN** для проекта задана команда подготовки и создан новый worktree
- **THEN** команда выполняется в новом пространстве, а её вывод и состояние сохраняются в данных пространства

#### Scenario: Подготовка не настроена
- **WHEN** новый worktree создан без настроенной команды
- **THEN** пространство доступно без дополнительных команд подготовки

#### Scenario: Ошибка подготовки
- **WHEN** команда подготовки завершается с ошибкой
- **THEN** ошибка сохранена отдельно от результата создания
- **AND** пространство и полученные файлы остаются доступными

### Requirement: Архивирование пространства

Ядро ДОЛЖНО (SHALL) позволять архивировать завершённое пространство и возвращать его в активный список без удаления файлов и истории. Команды сохранены в ядре; элементов архивирования и возврата в текущем интерфейсе нет.

#### Scenario: Архивирование и возврат
- **WHEN** команда ядра архивирует завершённое пространство, а затем возвращает его
- **THEN** оно скрывается из активного списка и вновь появляется после возврата
- **AND** файлы и история сохраняются

### Requirement: Защита работы при удалении worktree

Перед удалением Git worktree ядро ДОЛЖНО (SHALL) проверить несохранённые черновики, незакоммиченные изменения, неотслеживаемые файлы и несмерженные коммиты. Обнаруженная работа требует явного подтверждения в команде удаления; работающие сессии и терминальные процессы должны быть остановлены до удаления. Проверка и удаление доступны в ядре; формы удаления в текущем интерфейсе нет.

#### Scenario: Обнаружены изменения
- **WHEN** команда ядра проверяет удаление worktree с несохранённым черновиком, незакоммиченными либо неотслеживаемыми файлами или несмерженными коммитами
- **THEN** проверка возвращает обнаруженную работу, а удаление не выполняется до явного подтверждения

#### Scenario: Удаление отменено
- **WHEN** команда удаления вызвана без подтверждения
- **THEN** пространство, его файлы и черновики сохраняются

#### Scenario: Работа ещё выполняется
- **WHEN** команда ядра запрашивает удаление пространства с работающей сессией или терминальным процессом
- **THEN** удаление отклоняется с объяснением необходимости остановки

#### Scenario: Ошибка удаления
- **WHEN** операция удаления worktree завершается ошибкой
- **THEN** команда возвращает ошибку и сохраняет сведения о фактическом состоянии пространства для последующего действия

### Requirement: Раздельное удаление ветки и папки

Ядро ДОЛЖНО (SHALL) требовать отдельного подтверждения в команде удаления ветки. Удаление пространства обычной папки ДОЛЖНО (SHALL) убирать его из приложения, сохраняя исходные файлы и историю разговоров.

#### Scenario: Удаление пространства без удаления ветки
- **WHEN** команда ядра удаляет worktree без отдельной подтверждённой команды удаления ветки
- **THEN** ветка сохраняется

#### Scenario: Удаление пространства папки
- **WHEN** команда ядра удаляет пространство обычной папки
- **THEN** пространство убрано из приложения
- **AND** папка, вложенные репозитории и история разговоров остаются
