# Yade

Локальное настольное приложение. Реализованы основа, проекты и пространства, терминал, настройки, разговоры с исполнителями, редактор, Git и жизненный цикл из этапов 2–11 [плана](docs/implementation-plan.md). Этап 12 добавляет сборку `.app` со встроенным Node.js и ручное обновление. Реальная подписочная проверка Claude и сквозная приёмка остаются открытыми.

Планируемые типы файлов редактора, подсветка, иконки и границы поддержки зафиксированы в [EDITOR_FILE_TYPES.md](EDITOR_FILE_TYPES.md).

Для Go и TypeScript/JavaScript доступны навигация по коду, автодополнение, подсказки типов, диагностика и переименование с предварительным просмотром. Установка поддержки и сочетания JetBrains описаны в [навигации по коду](docs/code-navigation.md).

## Разработка на macOS

Нужны Xcode Command Line Tools, Node.js 26.8.1, npm и Rust 1.90 или новее с Cargo в `PATH`. Проверено на macOS с Node.js 26.8.1, npm 11.19.0 и Rust 1.99.1.

```sh
npm ci
npm run desktop
```

`desktop` запускает Vite на `127.0.0.1:1420` и окно Tauri. Только интерфейс: `npm run dev` (команды ядра доступны в настольном окне).

Основной интерфейс использует компоновку в стиле JetBrains: проект и Git слева, редактор в центре, терминалы снизу, разговоры справа. У каждой области свои вкладки; открытие разговора или терминала сохраняет выбранный файл. Кнопки на боковых полосах скрывают панели без остановки работы, разделители меняют размеры. Ширина проекта сохраняется в базе, остальные размеры и выбор панелей — в локальном хранилище окна.

Горячие клавиши для macOS: `⌘K` — проекты и пространства, `⌘⇧O` — файл, `⌘⇧F` — поиск по содержимому, двойной `Shift` — файлы и символы. `⌘T` открывает меню новой вкладки, `⌘⇧Space` переводит к сообщению, `⌥F12` — в терминал. Если разговора нет, открывается выбор исполнителя; если терминала нет, создаётся обычный терминал. `Ctrl+Tab` / `Ctrl+Shift+Tab` переключают вкладки текущего пространства по истории использования; отпускание `Ctrl` подтверждает выбор, `Escape` отменяет. `⌘W` закрывает вкладку с фокусом, сохраняя файл; выполнение разговора или терминала продолжается, окно остаётся открытым. `⌘1` / `⌘9` показывают файлы / Git, `⌘S` сохраняет файл, `⌘,` открывает настройки.

В разделе «Настройки → Горячие клавиши» доступны поиск команды или сочетания, запись нажатием клавиш, отключение и возврат каждой команды к исходному сочетанию, а также сброс всех назначений. При конфликте можно явно переназначить сочетание, отключив прежнее назначение. Изменения применяются сразу и сохраняются для всех проектов на устройстве. Сочетания используют физические клавиши и работают в русской раскладке. Навигация по коду действует в редакторе; команды оболочки остаются терминалу, открытые диалоги блокируют посторонние команды. Отправка сообщений сохраняет прежнее поведение.

Настройки также открываются шестерёнкой на левой панели; плюс на верхней панели сразу открывает «Новое пространство» для выбранного Git-проекта. В редакторе раскрывается отдельный блок сравнения версий.

В разделе «Внешний вид» отдельно выбираются шрифты интерфейса, чата, редактора и терминала, общий масштаб, перенос строк кода и форматированный либо исходный текст сообщений. Предпросмотр и приложение меняются сразу; выбор сохраняется на устройстве для всех проектов. Inter и JetBrains Mono входят в сборку и работают без интернета. Раздел «Исполнители» сохраняет отдельные настройки пространства и сессии.

При наличии локальных файлов прототипы открываются в режиме разработки по `http://127.0.0.1:1420/?prototype` и `http://127.0.0.1:1420/?prototype=search`. Терминал и разговор в прототипе работают локально без подключения к ядру. Основное приложение запускается через `npm run desktop`.

## Проверка и сборка

```sh
npm run build
npm test
cargo test --locked --manifest-path src-tauri/Cargo.toml
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
npm run desktop:build
npm run desktop:check
```

Зависимости закреплены в `package-lock.json`, `executors/runtime/package-lock.json` и `src-tauri/Cargo.lock`. `desktop:build` создаёт `src-tauri/target/release/bundle/macos/Yade.app`. Установка, требования к CLI, проверка ручного обновления и восстановление совместимой базы описаны в [инструкции поставки](docs/desktop-delivery.md).

SQLite хранится отдельно от приложения: `~/Library/Application Support/dev.yade.desktop/state.sqlite3`. Перед ручным копированием базы приложение нужно завершить.

## Доступный сценарий

1. Добавить группу при необходимости, затем нажать «Добавить папку» и выбрать существующую папку в системном окне. Путь и название заполнятся автоматически; перед сохранением можно изменить название и группу. Путь также можно ввести вручную. Git-репозиторий или обычная папка регистрируется с основным пространством. Для группы можно задать и открыть общую родительскую папку.
2. Выбрать проект и пространство. Открыть или закрыть обзор, изменить ширину боковой панели.
3. Завершить приложение и открыть снова: выбранный проект, пространство, вкладки, их порядок и ширина панели восстановятся. Сохранённые сессии отображаются без запуска исполнителей; продолжение требует нового сообщения пользователя.
4. Открыть «Все проекты» и нажать «Новое пространство» у Git-проекта либо нажать плюс на верхней панели. В отдельном окне указать название, исходную ветку или коммит (`HEAD` по умолчанию) и при необходимости новую ветку. Стрелка справа от исходной точки открывает список локальных и известных удалённых веток с поиском; `HEAD` и хеш коммита можно ввести вручную. «Создать пространство» создаёт Git worktree по пути `~/yade/workspaces/<имя папки репозитория>/<название пространства>`; вручную вводить путь не нужно. При пустом поле новой ветки рабочая копия открывается с отсоединённым `HEAD`. Подробности — в [MVP](docs/mvp.md#реализованный-сценарий-третьего-этапа).
5. Для пространств интерфейс предоставляет создание и выбор; промежуточное окно управления убрано. Архивирование, удаление и настройка команды подготовки сохранены в командах ядра, но в текущем интерфейсе недоступны. Их поведение описано в [MVP](docs/mvp.md#реализованный-сценарий-третьего-этапа).
6. Нажать «Новый терминал» в пространстве. Можно открыть несколько оболочек, вводить команды, менять высоту терминала и прерывать команду через Ctrl+C. Закрытие вкладки сохраняет процесс; кнопка с именем терминала возвращает его представление. «Завершить терминал» останавливает выбранную оболочку и её дочерние процессы. Состояние и код выхода отображаются отдельно. Подробности ограниченной очереди и восстановления вкладки описаны в [архитектуре](docs/architecture.md#терминал-реализованный-четвёртый-этап).
7. Открыть «Настройки исполнителей»: проверить версии и штатный вход, выбрать пространство и исполнителя, модель и разрешения. Параметры проверяются без отправки сообщения и сохраняются для следующего запуска; штатные значения не переопределяются без выбора. Доступны отдельные параметры сохранённой сессии. Версии, команды входа и границы проверки описаны в [совместимости](docs/executor-compatibility.md#реализованный-пятый-этап).
8. Выбрать исполнителя, указать название и нажать «Новый разговор». Доступны несколько вкладок, поток ответов и действий, разрешения и вопросы, команды и вложения, остановка и явное продолжение. Закрытие вкладки сохраняет выполнение; «История разговоров» открывает в том числе историю удалённых пространств. Её удаление подтверждается отдельно. Подробные шаги и ограничения приведены в [MVP](docs/mvp.md#реализованный-сценарий-восьмого-этапа).
9. Закрыть окно и вернуть его через Dock: ядро и задачи продолжают работать. Cmd+Q запрашивает подтверждение при активной работе, ждёт сохранения черновиков и завершает процессы. После сбоя восстановленные разговоры не запускаются сами; сохранившиеся процессы требуют проверки. Порядок действий и границы восстановления описаны в [архитектуре](docs/architecture.md#выход-и-восстановление-реализованный-одиннадцатый-этап).

Ошибка команды или сохранения показана в интерфейсе; неуспешное изменение расположения не заменяет сохранённое. База хранит группы, проекты, пространства, сессии, запуски, сообщения, события, черновики и настройки. Удаление пространства обозначается отдельным состоянием и не удаляет историю каскадно.

Ядро проверяет `workspaceId`, `sessionId` и `runId` совместно. Событие `run-event` содержит этот контекст и сохранённый порядковый номер. Запись события предшествует его публикации. Начальный реестр процессов на Unix создаёт отдельную группу процессов, сохраняет связь с запуском и удерживает дескриптор лидера до принудительной остановки дерева; PID из базы сам по себе не даёт права завершить процесс.

Функциональные проверки: реальные временные базы SQLite (повторное открытие, связи, откат неудачной миграции, отказ записи), временное дерево процессов и независимый процесс, переключение и восстановление интерфейса с подменённой границей команд. Тесты этапа 11 проверяют отмену и подтверждение выхода, ожидание записи черновиков и восстановление после принудительного завершения отдельного процесса, включая оставшиеся процессы и устаревший PID. На macOS ранее проверен запуск окна собранного приложения; системные действия закрытия, Dock и Cmd+Q с работающими задачами отдельно не проверялись.
